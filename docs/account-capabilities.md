# 账号能力、QQ 恢复与 0.12.0 当前验收

0.13.0本轮按用户最新安排不再进行真实模型、QQ或其他社交平台验收。QQ资料／头像／空间功能由用户自行测试；其他社交连接统一显示“未测试”，但驱动支持、授权、连接与送达状态仍各自如实显示。下文0.12.0的待扫码、离线及未验收项仅保留当时观察，不等于本轮又要求用户扫码，也不自动升级为已解决。当前版本记忆改造见[时间线说明](memory-timeline-and-context.md)。

0.12.0 增加个人 QQ 的头像、资料和空间说说账号工具，修复管理口认证／限流和离线无二维码的恢复流程，并让设置页说明真实能力来源、许可和在线状态。`persona-memory/3`、八个人格工具和人格自主判断边界保持兼容。工具是否已接线、隔离测试通过、正式宿主实际加载、平台确实完成操作是不同证据。

在已授予当前人格、当前QQ账号的工具能力范围内，是否修改自己的头像、昵称、签名、性别资料，具体使用什么内容以及何时修改，均由人格自主决定。程序不设固定更换周期、次数或触发条件。

使用入口：**DSH 设置 → 相续人格 → 连接 → QQ → 能力与权限／账号操作记录**。普通文字聊天、语音消息与实时通话是不同能力；勾选许可不会补齐驱动缺少的接口。权限不会自动全开，也不规定人格什么时候、对谁或怎样使用。

## 个人 QQ 新增的三种账号操作

| 操作 | 使用的既有许可 | 参数与真实结果 |
|---|---|---|
| `profile.avatar` | `profile.update` | `assetId` 取当前人格已保存的图片资产；仅接受本机桥已核实的成功回执。 |
| `profile.update` | `profile.update` | `nickname` 必填，1–64 个 Unicode 字符；`signature` 可选、可空，最多 512 字符；`sex` 可选 `unknown/male/female`。桥返回 `data.result===0` 才确认完成；明确非零为失败，缺结果为未知。 |
| `feed.publish` | `feed.publish` | `text` 最多 16000 字符，有图时可空；`imageAssetIds` 最多 9 个且不能重复；必须明确 `visibility`。只有真实 `tid` 才确认空间说说发布完成。 |

空间可见范围为平台参数：`1` 公开、`4` 好友、`16` 部分好友可见、`64` 仅自己、`128` 部分好友不可见。`targetUserIds` 最多 100 个不重复的真实 QQ 号；仅在 16／128 时必须非空，其他范围不能附带非空对象列表。这是平台字段校验，不替人格选择内容或受众。

图片只引用当前人格的真实 `asset-<32hex>` 资产，不接受任意本地路径、URL 或模型伪造的图片数据。每张最多 8 MiB，单次总量最多 16 MiB，最多 9 张；读取时复核图片容器、MIME、实际字节和 SHA。技术收据只留资产 ID／SHA／大小／MIME，不嵌入图片 Base64、路径或密钥。

能力仅在桥身份和账号已核实时提供；当前桥分支只对精确 NapCat 4.18.41，或 `get_supported_actions` 明确报告相应 action 的驱动宣传对应动作。不把未来所有 NapCat 版本视作自动兼容。完整入口与回执语义见[QQ 账号操作](qq-account-operations.md)；字段唯一权威为[persona-schema 第25节](plan/persona/persona-schema.md#0120-account-and-recovery-contract)。

## 登录和管理连接分开判断

- **管理连接受限**：显示本机管理认证的 60 秒冷却及具体代码，页面只做本地倒数，到期后点“重新检查连接”。上游 HTTP 200 内的 Unauthorized 也作为认证失败处理。管理认证问题本身不能证明 QQ 已离线。
- **上次在线、管理口不可达**：页面标明上次核对时间和账号，当前登录状态待核对，不拿缓存 `connected` 或旧二维码冒充新确认。
- **已核实离线且没有二维码**：后台明确 `recovery.required/canRecover` 后提供“重新连接 QQ”。本人一次点击重新打开本次受管登录流程；先验证属于本应用的启动代次、PID、进程树和监听端口已经停止，不能确认就明确失败，不按进程名结束其他 QQ。
- **有当前有效二维码**：才提示用手机 QQ 扫码。手机已确认但核心尚未就绪时等待实际登录完成，不重复刷新二维码。

同页读状态、重连和刷新动作只允许一个进行中请求；错误态停止 2.5 秒自动轮询。页面隐藏或离开停止 UI 轮询，恢复可见仅做合适的只读核对并尊重冷却。管理口共享认证单飞；不以反复登录冲撞限流，不自动执行重新连接、QuickLogin 或 RefreshQR。

等待登录且管理连接已核实ready时，明确的`NAPCAT_LOGIN_ERROR`不会让用户失去手动换码入口：二维码即使被错误状态隐藏，仍可点“重新生成二维码”。仅本人点击才调用换码；普通poll／重新检查连接不自动换码。认证或限流、未知状态、需要重连、手机已确认、初始化中或已在线时均不换码，旧flow和并发点击也不能越过当前状态。后台实际Refresh成功后重新读取CheckLoginStatus，不用旧登录错误覆盖新二维码；专项与真实过期码刷新验收分别记录。

重连沿原人格、实际账号和已保存接入范围／许可恢复，不扩大权限或重置记忆。已有登录是否仍可缓存恢复由实际 QQ 状态决定；新二维码仍须本人确认。前一阶段确实观察到正式宿主冷恢复同一个仍存活的受控QQ，没有第二次spawn，也无需新QQ扫码；之后一次重启停止了该受控进程，本次最终运行已启动新的受控QQ并核实新归属证明，目前等待本人重新扫码，OneBot API尚不可用。主QQ保持运行且未受影响。早期在线恢复不能代替当前重新登录，也不证明所有退出路径或优雅关闭均已通过。

上次启动若仅留下未核实的 `launching` 记录，后台会以 `NAPCAT_OWNED_LAUNCH_UNVERIFIED`／`manualCloseRequired` 明确要求本人确认并关闭旧受管 QQ。它阻止重复启动：旧 WebUI 没有监听也不能再开第二套。程序不会按时间自动回收这条屏障，也不会凭未核实记录收养或停止进程；这项边界不代表新版真实重连或账号写入已验收。
