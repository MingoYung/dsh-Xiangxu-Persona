# QQ、微信聊天渠道与本机声音

版本0.4.1，修订日期2026-10-26。这里的移动端指用户已有的QQ、微信等聊天软件。插件把平台私聊和群聊接入同一份持续人格；第七页是“聊天渠道与语音”。个人网页聊天与Telegram暂为后续接口，不是本版开启入口。

## 当前能力与前置条件

| 渠道 | 当前适配 | 运行前需要 | 已验证边界 |
|---|---|---|---|
| QQ | OneBot11文字私聊/群聊；标准record语音按实际能力使用 | 用户已运行并登录的NapCat等兼容本地桥、HTTP API地址、账号ID及相应鉴权 | 原生DSH与模拟OneBot HTTP贯通；尚未登录真实QQ账号做端到端测试 |
| 微信 | OneBot12兼容桥的文字私聊/群聊路由 | 用户自行提供具备相应能力的微信本地桥 | 模拟OneBot12私聊/群聊已贯通；微信官方接口当前不提供本方案所需普通群聊能力，不能据此宣称真实微信群可用 |
| Telegram | 预留渠道接口 | 后续适配 | 本版没有连接或发送入口 |
| 个人网页 | 保留实验源码与未来接口 | 后续明确启用与部署工作 | 本版不挂载网页聊天服务，安装包不交付手机网页主入口 |

本版将已有兼容桥的参数默认折叠到高级配置，适合已经准备好桥的用户。扫码向导、自动发现并接管桌面已登录的QQ／微信尚未实现；没有桥时无需填写这些高级字段，本机音色试听可以独立使用。

配置入口不替你安装或登录平台。本版需要实际桥地址和账号后，才能完成该账号的连接检查及平台往返；没有这些信息时，页面应显示未配置、未连接或具体错误。桥的连接成功、模拟HTTP成功、平台真实收件和用户已读是不同证据。

## QQ接入步骤

1. 按[NapCat上游文档](https://github.com/NapNeko/NapCatQQ)准备并登录自己的QQ账号，开启兼容OneBot11的HTTP服务。在桥中将消息上报格式设置为消息段数组；本插件不从CQ码或昵称猜测原始消息。
2. 打开DSH“设置 → 相续人格 → 聊天渠道与语音”，展开已有OneBot兼容桥的高级配置，在QQ卡填写本地桥API地址、账号ID以及桥要求的API访问令牌。API令牌留空会保留已保存值；勾选明确清除才移除旧值。
3. 填写要接入的私聊对象ID和群ID。空列表表示该范围尚未接入；只有明确填写`*`才接入该账号相应的全部私聊或群聊。这些是用户选择的渠道范围，不决定人格该不该回应、关注谁或怎样相处。
4. 生成事件上报令牌，把页面给出的回调地址和本次令牌填入本地桥的HTTP客户端/事件上报设置。默认回调为`http://127.0.0.1:17654/channels/qq/events`，鉴权使用`Authorization: Bearer <本次上报令牌>`。令牌只在生成时显示；重新生成会使旧令牌失效。
5. 保存配置并检查连接，再明确启用接入。只有本地桥确认实际账号匹配且在线，才接受该配置的事件和发送目标。尚未接入范围的最近对象/群只显示有限ID元数据，方便用户核对后自行添加，不保存其聊天正文。

该回调默认只监听本机地址，并且默认没有listener；它是已配置平台桥的事件载体，不是让手机浏览器直接连接的网页服务。插件不创建公网隧道、不修改防火墙，也不提供通用管理RPC转发。

## 微信接入

展开高级配置后，微信卡使用OneBot12协议：填写兼容桥的API地址、桥实际报告的账号标识、API令牌、私聊/群接入范围，并使用`/channels/wechat/events`事件回调。上报数据必须保留`self.platform=wechat`、稳定账号/发言者/群标识、消息ID、发生时间与消息段数组；发送请求携带对应`self`和明确私聊或群目标。

OneBot12只是适配契约。现有微信工具可能仅支持私聊；本版不会把一个私聊桥标成已经支持群聊，也不将微信官方接口当成普通微信群聊API。页面和结果以配置桥的实际能力与回执为准。当前没有用户真实兼容桥可供验证，因此本版不能写作“已连接QQ或微信群”。

## 同一个人格与真实来源

平台、账号、私聊/群房间和实际发言者分别保留。每个“房间＋实际发言者”使用稳定的原生聊天通道，避免把整个群认成同一个人；不同通道仍使用同一个人格核心。外部账号、群ID、昵称和sessionId都不是自动分配的personId，是否认出同一个人仍由人格判断。

接入的原话经DSH原生inbox先持久化，再沿既有记忆、注意、主动、等待与睡眠机制处理。`sourceAt`保留平台发生时间，宿主接收时间另外保留。user原件保持user，assistant原件保持assistant；关系归属不改变实际发言者。图片、语音等尚未读取的消息段如实标明，不把占位文本或alt_message当作用户原话。

专用IM会话只提供五个人格工具：`memory_search`、`memory_forget`、`persona_introspect`、`persona_decide`、`persona_voice`。平台消息不会获得Harness编码工具、文件操作或通用会话控制入口，也不改变用户其它DSH会话的工具配置。没有增加必须被@、每日次数、最短间隔、话题门槛或强制成长规则。

## 发送、主动与睡眠

原生inbox已持久化只表示收到来信。模型生成一段最终文字，也不等于已经在QQ/微信发出。只有平台桥返回明确成功及稳定消息ID后，才将对应正文计作实际说过；超时、缺回执或失败保持未知/草稿过程，用户待处理原文不会因此被假清除。

人格选择的主动消息仍沿已有持久计划和真实通道投递。睡眠来信保留为待处理，实际唤醒后回到相应目标；没有为了接入群聊而改变人格自己的睡眠、注意或回应选择。

平台发送先保存prepared回执。相同源事件不重复外发，冷启动遗留prepared转unknown，不自动付费重放。对账只使用真实平台回执；有确认但本地投影缺口时，按已确认来源定位原文，不从“DSH已经生成”推断“平台已经收到”。

## 本机语音的选择与限制

本版采用Windows现有`System.Speech`音色合成WAV，再交给支持音频的渠道桥。这样能为IM提供实际音频文件，无需新增Python环境或下载TTS模型。使用的是已安装声音，不是本轮训练或克隆的新音色。其它系统缺少对应引擎时明确报告不可用，文字模式仍可使用。微软接口依据见[SpeechSynthesizer](https://learn.microsoft.com/en-us/dotnet/api/system.speech.synthesis.speechsynthesizer)。

声音偏好有“人格自己选择”和“由我指定”两种模式。人格通过`persona_voice`按需查看实际音色目录并保存选择；不按性格标签硬映射，不强迫每轮重新挑声音。用户模式使用用户设置，同时保留人格偏好供切回自主模式时使用。明确指定的音色不可用时如实失败，不悄悄换为在线声音。

QQ的标准record音频交付需要本地桥实际确认`can_send_record`。当前微信OneBot12适配不宣称语音发送能力。回复形式含义为：

- `text`：发送完整文字。
- `both`：文字成功可以记录为实际交付；若合成或音频发送不可用，另记`voiceUnavailable`，不冒称语音也成功。
- `voice`：要求实际语音合成及平台音频回执；不可用或失败时明确返回结果，不擅自改发文字。

本机语速映射为近似SAPI音级，不承诺与浏览器倍率逐点等价。当前引擎能力`pitch:false`；非默认音高不能伪称已经应用，也不静默把人格选择改成另一数值。短试听生成后由用户点播放器播放，不自动发到聊天平台，不写入人格经历。

本机已实际生成过中文PCM WAV，并校验音频结构；没有播放到声卡，也没有将这份声音发到真实QQ/微信。浏览器SpeechSynthesis仅作为未发布网页原型保留，不能用其设备播放结果冒充IM音频生成。Edge在线TTS未被当作本地方案或默认依赖。

## 有限资源、恢复与撤销

| 载体 | 技术上限与行为 |
|---|---|
| 平台登记/回执 | 独立于人格备份的`xiangxu-channels/1`登记，最多1MiB；两个平台档案、128个binding、每类接入范围最多256个ID |
| 事件与排队 | 回调正文64KiB，串行工作队列32；OneBot文字单条16000个Unicode字符，不截断后冒称完整 |
| 去重回执 | 总数2048，未确认最多256，终态保留目标1024；prepared/unknown不静默淘汰 |
| 有限去重窗口 | 终态淘汰后保留源时间floor/出站序号高水位；过期未知入站明确非2xx拒收且不送模，旧出站不重发、不伪造已送达 |
| 声音偏好/目录 | `voice/profile.json`最多16KiB；目录只在内存，最多8会话、每会话32音色、总32KiB，不每轮注入整目录 |
| 本机音频 | 单次合成最多2000个Unicode字符、单文件8MiB、最多4文件/总16MiB缓存、60秒进程时限；超限不截断后冒充完整朗读 |

登记不保存聊天正文；API令牌只存本机受限登记，入站鉴权只存哈希。状态只返回是否已设置令牌。不得把真实令牌、聊天记忆库或认证地址提交到仓库。

普通暂停/停用保留明确配置与已有去重状态，忙碌会话先完成再切换。恢复指定人格根时使其旧binding退休并增加代次，停用相应接入；用户明确再启用后使用新通道，不复用已退休宿主对话来复活旧经历。保留回执继续阻止旧平台事件重放，已明确遗忘仍由核心撤销链防复活。

## 当前修订与历史验证边界

0.4.1只修订宿主样式融合、布局及日常操作说明，原生GUI实际范围见[当前界面说明](management-ui.md#041-当前界面与验证范围)。以下数量与音频、截图记录均为0.4.0历史结果；本版未把它们重新计为已执行的336项或67项验收。

完整本地回归 **336/336通过**，29份已记录运行源码SHA前后一致，79个JS/MJS的语法/核心独立性/包入口检查通过；具体范围见[完整回归摘要](verification/0.4.0-tests.json)。该回归包含明确保留的实验源码测试，不表示个人网页已发布。

最终原生SDK渠道专项 **67/67通过**：真实DSH引擎、固定模拟模型和loopback模拟QQ/微信桥。实际42个宿主请求与42个fixture请求均为`persona-social-fixture/fixture-v1`，共11次模拟HTTP发送（QQ7、微信4）。覆盖两平台私聊/群聊、同群不同actor隔离、共同人格、自主私聊目标、重复回调、等待/睡眠/明确唤醒、真实来源时间及未知发送不进入已说C1，详见[最终SDK与音频摘要](verification/0.4.0-sdk-fixture.json)。
