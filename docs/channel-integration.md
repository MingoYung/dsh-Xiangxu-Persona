# QQ、微信聊天渠道、权限与本机声音

0.13.5技术补修见[记忆定位、发送前复核与关闭顺序](0.13.5-technical-safety-fixes.md)。本轮不重启DSH、不访问正式记忆正文、不调用生产模型或QQ实测；不把这些修复当作此前DSH Host启动超时的已证根因。旧版验收保留原范围，人格自主判断不变。

版本0.11.0，修订日期2026-10-27。这里的移动端指用户已有的QQ、微信等聊天软件，主入口是“连接”；插件接入同一个持续人格。个人网页与Telegram保留未来接口，本版不挂载手机网页服务。

“已支持”表示连接器实现相应协议，不能代替该账号实际资质或真实往返验收。0.10.1及更早记录没有个人QQ／微信群真人往返，模拟平台记录只证明相应隔离链路；0.11.0的安装、本人扫码、正式人格接入和私聊／群聊回执分别见[本轮最终验收](qq-one-click-setup.md#0110-final-acceptance)。二维码来自本次真实登录或绑定任务，由本机渲染，不把任意手机网页链接冒充账号登录。

## 连接流程（0.10.0，沿用分步操作）

“连接”首页提供QQ、微信、B站、声音、社交身份、QQ动态扩展六个目的入口；可选翻唱服务在“创作”中。QQ默认先提供个人QQ受管准备与扫码，之后核对账号并确认默认自主社交，接入当前已加载人格；官方Bot与“使用已有兼容桥”为次级入口。微信、B站继续沿各自扫码流程。“能力与权限”单独查看，不把全部高级字段铺在扫码页面。受管NapCat负责准备自己的运行目录和回调，已有桥方式仍要求实际可用服务，手机确认仍由本人完成。

0.8.0只重整管理界面的导航、内容层次与交互流程，core/、adapters/和运行时schema相对0.7.0未改，八个人格工具与persona-memory/3保持兼容。本版[完整本地回归](verification/0.8.0-tests.json)605/605通过，失败／取消／跳过均为0；UI与宿主专项55/55（50项UI＋5项host）属于同批验证，不另算独立需求。[真实DSH界面](verification/0.8.0-native-ui.json)完成5个主入口与16项任务式旅程、浅深主题及保存回读，使用隔离样本、无真实模型或平台调用。[后端兼容回执](verification/0.8.0-backend-compatibility.json)逐SHA核对50份后台及配套文件，继承0.7.0 SDK证据，未声称重新执行本版SDK。0.7.0的583/58/35与当时九页GUI保留历史含义；远程CI和发布状态另以实际结果为准。

## 账号与社交身份

“连接 → 社交身份”可从已实际连接的QQ／微信核对后登记，也可先登记用户自行注册的B站、抖音或其它平台账号。手工档案只表示人格与账号的关联，不产生登录态或执行权；当前没有适配器的平台明确未连接。同平台仍只有一个活动连接，多个档案不代表并发登录。owner social.inspect/list/upsert/remove/linkCurrent/refresh使用当前人格实例，persona_platform action:accounts只读目录。默认32条／人格、总256条／256KiB，另有字段与能力目录上限，不另存Token或Cookie。

实际账号、适配器支持、用户许可和当前可用分别核对；取消身份登记不会自动退出平台或删除记忆。完整字段和状态见[深刻记忆与社交身份](memory-reflection-and-social-identities.md)。

## 个人QQ一键准备与接入

[个人QQ操作说明](qq-one-click-setup.md)按准备、本人扫码、确认默认自主社交、接入当前人格说明。Windows x64受管入口复用已核实的QQ安装，固定版本下载并校验NapCat，在独立目录配置WebUI、OneBot API与事件上报；不替换QQ安装包、不捕获已有桌面窗口登录态。新启动的桥QQ仍会正常读写自己的用户数据。

默认自主社交在本人确认后将该独立QQ的私聊与群聊均接入，connect的allowedPrivateIds／allowedGroupIds为['*']；不要求用户逐个选择联系人或群。指定对象范围作为可选隐私／测试设置，仍控制平台通路。联系谁、是否尝试加好友、回不回复由人格决定，不由范围页面替人格预选。停止只处理本应用通道与可证归属进程，不能确认QQ全树退出时如实提示人工关闭。恢复仅沿已经成功接入的同实例／同根与原启用范围，不自动下载、换账号或扩大范围；明确停止清除恢复意愿。

### 好友能力的当前接线状态

入站好友申请与主动添加是两项不同工具能力。NapCat固定版已有set_friend_add_request处理真实入站申请，插件的申请事件／回应链仍未接线。主动申请在公开OneBot注册表仍缺action，本轮通过原创原生适配器补friend.query与friend.request源码接线；正式宿主加载后的工具实测另验，不能用已成功的一次操作者诊断代替。权限、查询引用、原始档案和真实结果分层见[QQ账号操作](qq-account-operations.md)。

## QQ官方发送策略

腾讯官方文档顶部说明主动推送自2025-04-21起不再提供，同页下方仍留旧额度。当前官方driver以取消主动推送为准，返回deliveryPolicy.proactive:false和passiveReplyRequired:true；没有有效被动回复上下文时返回QQ_PUSH_UNAVAILABLE，不伪造发送回执。私聊被动窗口60分钟，群聊5分钟；实际API仍可能受账号条件拒绝。该限制只适用于官方QQ，不套用到OneBot桥；人格仍可以自主决定想主动联系，执行器只报告当前平台实际能否完成。依据：[腾讯官方发送文档](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)，核对2026-10-26。

## 官方QQBot／微信扫码步骤（次级方式）

1. 先在“设置 → 人格与记忆库”加载实例，打开“连接”，选择QQ或微信。向导申请平台绑定任务，显示真实二维码、状态与过期时间。
2. 用自己的手机在对应应用内扫码并确认。验证码只用于这次绑定，不作为设置保存。未确认、取消、失败、过期与已授权分别显示；结果未知先查询同一绑定任务，不重复创建。扫码只能由本人完成。
3. 授权后核对账号与驱动支持的私聊／群聊范围。微信官方只显示私聊；QQ群选项不代表账号已获所有群权限。空列表未接入，只有用户明确选择相应全部范围才保存为`*`；微信默认可选择本次配对对象。点“完成连接并启用”后才开始接收。
4. 展开“能力与权限”，按需许可当前驱动支持的项目；页面分别显示支持、许可、可用及不可用原因。未许可项目不能通过人格工具执行，勾选也不能创造平台未实现的能力。
5. 需要停止时关闭接入；“断开连接”先停止接收并删除本机保存的该连接凭据，不声称已撤销平台端授权。平台远程授权需在对应平台管理。仅取消本次扫码不会自动删除已有聊天记忆。

本人确认后凭据仅保存在本机独立连接登记；页面只显示hasCredentials，不返回Token或AppSecret。本节官方绑定不要求个人客户端安装，也不抓取桌面登录态、创建公网隧道或修改防火墙；0.11.0个人QQ的受管NapCat准备按前节单独执行，不与官方Bot绑定混称。扫码和高级桥是不同接入方式，改方式／账号会退休旧原生绑定，避免沿用旧账号的聊天源。

## 实际能力与用户许可

权限按“人格实例＋平台＋实际账号”保存。检查、保存、列出和恢复默认分别是owner动作`permissions.inspect({id})`、`configure({id,allowed})`、`list({id})`、`reset({id,accountId})`。普通保存不由前端指定另一个账号或目录；切换账号不会套用旧账号授权。默认文字可用，迁移旧语音设置时保留其已选语音意图，但实际支持和就绪状态仍需核实。高级列表可恢复不再使用的账号权限，最多保存128条／256KiB；恢复默认会移除该账号的自定义许可，并恢复渠道默认许可：文字，以及渠道voiceMode中已开启的语音意图。它不删除聊天记忆、不自动重连，语音仍须驱动支持、引擎和连接就绪；返回defaults列出实际默认项。

| 能力ID | 面板含义 | 当前边界 |
|---|---|---|
| chat.text | 文字消息 | 仍需已接入目标与平台回执 |
| chat.image / chat.video / chat.file | 图片／视频文件／普通文件 | 使用已保存的媒体assetId和实际字节；视频文件不等于视频通话 |
| chat.voice | 语音消息 | 官方QQ和微信缺少已验证的PCM WAV发送编码链；QQ OneBot11按实测record能力使用，微信OneBot12不宣称支持 |
| chat.sticker | 驱动实际实现的表情 | 当前QQ NapCat适配仅发送系统face ID，未实现自定义表情包mface上传；官方QQ／微信未实现此项 |
| message.reply / message.retract | 引用消息／撤回自己的消息 | 必须使用真实消息ID，只有驱动实现的动作可执行 |
| contacts.read / groups.read | 联系人／群列表查询 | NapCat或明确列举对应action的桥可查询有限结果，官方QQ／微信未实现；不获得任意客户端控制 |
| friend.query / friend.request | 查询QQ联系人与加好友设置／主动申请 | 原创固定版本原生适配已在源码接线；实际可用同时核owned启动、账号、就绪和一次工具许可，正式宿主验收另列 |
| friend.manage / group.manage / profile.update | 处理收到的好友请求／群操作／账号资料 | 当前执行器未实现；入站处理上游已有但尚未接线，不因主动申请实现而宣称全部好友管理可用 |
| feed.read / feed.publish / feed.react | 平台资料／动态读取、发布与互动 | QQ需用户自备动态协议服务；B站按操作映射读取／评论；微信朋友圈仍未实现。实际支持与许可分别核对 |

## 已有OneBot兼容桥的高级配置

QQ使用OneBot11，微信使用OneBot12。准备并登录自己的兼容桥后，填写API地址、实际账号ID、API令牌和私聊／群列表；QQ上报必须使用消息段数组，微信保留`self.platform=wechat`及稳定账号／发言者／群标识。API密钥留空保留旧值，明确勾选清除才删除。

事件回调使用状态返回的实际callbackUrl，常见为`http://127.0.0.1:17654/channels/qq/events`或`/channels/wechat/events`。通用桥可沿用Bearer上报令牌；NapCat原生HTTP Client使用`onebot-hmac`，以专用token对原始JSON字节计算HMAC-SHA1，发送`x-signature: sha1=<hex>`，不能当成Bearer。受管向导自动配置；手动NapCat通过channels.rotateIngress选择authMode:onebot-hmac并将仅本次返回的secret填入HTTP Client token。旋转使旧secret失效；配置和状态不回显。回调保留Host／Origin／正文容量与排队后轮换复核，不通过URL参数放密钥。保存后核对真实账号与在线，再明确启用；官方绑定不使用此回调。

桥只有明确识别为NapCat，或get_supported_actions列举了相应操作，才报告扩展能力。NapCat提供系统face、引用、撤回、联系人／群列表与视频；图片还需can_send_image确认，语音另需can_send_record。自定义表情包、好友／群管理和资料修改没有因存在能力ID而自动开放。

已有兼容桥的空接入列表表示该范围尚未接入，显式`*`开放相应全部对象或群；0.11.0个人QQ默认自主社交向导会在本人确认连接时为私聊和群都保存['*']，指定对象模式仍可选。最近未接入目标只保留有限ID元数据，便于用户核对，不保存其聊天正文。高级API默认本机／私网字面地址或localhost，远程必须明确allowRemote且HTTPS；不接受URL凭据、查询令牌或fragment。

## 同一个人格与陪伴工具范围

平台、账号、房间和实际发言者分别保留；每个房间＋实际发言者使用稳定原生通道，但共用同一人格核心。外部ID、昵称或sessionId不自动等于personId；是否认出同一人仍由人格判断。原话经DSH原生inbox持久，保留平台sourceAt、接收时间、role与speakerId；关系重归属不改实际发言者。未读取的图片／语音段如实标记，不从占位文本猜原话。

所有“相续人格”主预设在普通DSH、IM、主动和唤醒中使用独立工具范围，当前八工具为memory_search、memory_forget、persona_introspect、persona_decide、persona_voice、persona_media、persona_platform、persona_task。人格通过persona_task自主创建独立新任务，显式工作预设处理工程／研究等过程；主会话按需回收结果、选择实际片段供原有自主整理。裸派发、Harness和编码工具不直接放回陪伴主会话，其它DSH预设不变。

工作会话与委派封套以宿主可信角色追踪，AI写的kind:user任务指令不会成为真人原话；任务详细过程和报告另行归档，主会话只自动留下导航事实。用户的平台授权仍按实际账号与渠道执行，创建worker不会获得新的平台或文件权限；在已有full-access环境中不宣称额外OS沙箱。原生`ctx.agents.create/resume`也继续用于真实接收／恢复通道。没有新增必须被@、主动次数、回复间隔、话题门槛或成长频率，详见[自主委派与任务档案](delegation-and-task-archives.md)。

## 发送、主动、睡眠与实际回执

原生inbox持久只表示收到来信，生成最终文字也不等于平台已发出。外发先存prepared，按同一源事件／操作编号去重；只有连接器取得明确平台回执才记为delivered和实际assistant。QQ等可返回平台消息ID；微信ret=0但没有远程消息ID时保存带client_id的API接受回执，并标明ID种类，不伪造远程消息ID或用户已读。超时、缺回执与冷恢复prepared保持unknown，不自动重发、不假清用户pending。

人格的主动消息沿已有持久计划与真实目标发送。睡中来信保留为待处理，唤醒后回到相应目标；接入群聊不改变注意、回复与睡眠选择。作品生成与平台发送分开报告：persona_media得到assetId，persona_platform仅对已支持、已许可的真实目标执行，使用实际资产字节与真实消息ID，不提供通用客户端遥控。

## 本机语音

Windows现有System.Speech生成WAV；其它系统缺引擎时如实不可用，文字仍可使用。不下载TTS模型、不训练／克隆音色，不把Edge在线TTS作为默认依赖。音色可由人格经persona_voice按需选，用户也可指定；无性格标签硬映射或每轮必选要求。用户模式下人格偏好仍可保存备用，明确音色不可用不静默换云端。语速近似SAPI音级，当前pitch:false；[微软SpeechSynthesizer文档](https://learn.microsoft.com/en-us/dotnet/api/system.speech.synthesis.speechsynthesizer)说明实际本机接口。

`text`发送文字；`both`可用真实文字回执记录交付，并另报voiceUnavailable；`voice`必须合成成功且渠道确认音频，否则明确失败，不擅自改发文字。官方QQ／微信当前都缺已验证的本机WAV官方编码转换链，微信OneBot12也不宣称支持。QQ OneBot11需要桥实测can_send_record。试听只生成短WAV，用户手动播放，不投递平台或写人格经历。生成、平台API接受、客户端收件和用户听到分别报告。

| 官方恢复上下文 | 每账号最多128项，更新游标16KiB；它们是传输路由事实，不向模型注入整份目录 |
| 高级桥登记／回执 | xiangxu-channels/1最多1MiB、128个binding、每范围256个ID；回调正文64KiB、队列32 |
| 有限去重 | 回执2048、未确认最多256、终态保留目标1024；prepared／unknown不静默淘汰。终态淘汰保留源时间floor／出站序号高水位，拒绝过期未知入站与旧发送，不伪造旧ack |
| 用户许可登记 | xiangxu-permissions/1，128条、256KiB；按当前实例／实际账号消费，不混入模型人格材料 |
| 声音偏好／目录 | voice/profile.json 16KiB；内存最多8会话、每会话32音色、总32KiB，按需查询 |
| 本机声音缓存 | 单次2000个Unicode字符、单文件8MiB、最多4文件／总16MiB、60秒合成时限；超限不截断后冒充完整朗读 |

这些帽分别作用于传输、元数据与文件，不是人格发言频率。图片／视频作品库和模型读取另有独立上限，见[形象与创作](media-and-identity.md)。普通停用保留配置与去重状态；恢复某人格根会退休其旧binding、增加代次并停用接入，明确启用后建新通道，保留回执阻止旧事件重放。明确遗忘沿核心永久撤销链清相关派生，不因重新加载、作品结果迟到或恢复旧档案复活。
