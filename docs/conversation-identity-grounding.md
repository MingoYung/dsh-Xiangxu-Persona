# 身份线索、话语对象与自主参与

2026-11-05 候选补修，基于 `22c7096`。本轮先修来源装配和基础辨认说明，未修改正式人格或重载现用代码，未增加真实模型调用。真实模型是否减少身份冒领仍待独立验证，不以固定模型结果代替。

## 三件事分别理解

当前自我资料描述人格如何认识自己；平台账号和实际发言者来自本轮通道路由；一句话可能在叫谁需要结合称呼、@、引用和上下文理解。理解对象以后是否参与仍是人格的选择。她可以在别人被叫名字时插话，也可以在自己被 @ 时选择稍后回应或沉默；接受新昵称、改名或开玩笑继续使用既有自主路径。

新增共享说明从 `core/onboarding.js` 的 `REFERENCE_UNDERSTANDING` 单处导出，原生 DSH 装配、core 回复和辅助控制请求消费同一文本。说明区分资料与判断，允许不确定，历史助手回复只表明当时说过的话，不自动确认相关称呼或身份。没有增加姓名白名单、关键词门、必须澄清、必须回复或禁止插话的分支。

## 实际补充的资料

QQ 每条群消息附带 `observationCoverage`：来源为保留的 accepted 同群入站与本条真实发言者，人数按平台 ID 去重，`completeGroupRoster:false`。昵称匹配只涉及已观察发言者的最新名字。空匹配不表示群里没有那个人，也不表示该称呼属于自己或他人。没有扫描完整群名单、增加网络请求、另调模型或把名字自动登记成人物。

`conversation_identity_reference` 在每轮外部文字通道装配中连接：

- 当前通道绑定的自身账号；
- 当前实际发言者账号和显示名；
- **同一人格快照**的 `self_profile` 版本与 current.name 呈现状态。

名字只引用既有自我资料，不复制一份可能过期的名字列表。`presented_in_self_profile`、`not_recorded`、`not_presented`、`unavailable` 分别表达呈现、未保存、未呈现与不可用，不把缺失资料补成某个名字。已有完整核心身份必须成功加载的机制不变。

该参考在原生必需投影中核验，普通 DSH 会话不会被编造平台账号。原丰富消息渲染格式保留，旧消息、引用、原文、角色和来源 ID 不迁移不改写。

## 记忆与昵称

旧助手说过“我在”或自称某名字，记录的是她当时的表达。旧话原样保留，不因这次修复删除、替换或判作无效记忆；人格可以重新理解过去。当前保存的自我描述与旧助手原话可以同时呈现。昵称接受仍由人格经原有自我档案接口表达，不要求程序或第三方审核认领，也没有把当前 name 变成只能使用的称呼。

本轮真实失败没有记录完整模型输入，因而“旧记忆反馈导致本次冒领”和“模型没有得到某项资料”均未被确认为根因。用户截图中的新回复明确自称他人；旧的“在呀”也可能只是插话，不能单凭旧句断言同等身份错误已发生。

## 验证与限制

回归覆盖未出现第三人、先前出现成员、同名不同账号、改昵称、观察窗口不完整、真实 @／引用、自主昵称更新、旧助手原文保留、reply／wait／listen 可用，以及同一快照的身份参考装配。新共享说明增加固定输入开销；生产 2970 快照预算、分页算法及 5000 字符拒绝回归保持。小输入正例只按新增固定说明的实际序列化长度调整合成测试容量，不调整生产容量。

实际 DSH 固定 provider 加本地模拟 QQ 验证了：第一条群来信“熙熙熙熙在么”没有 @，模型输入实际包含空匹配、观察不完整、自身账号和 current.name“阿序”；固定回复仍能主动加入话题并发送。随后实际 @ 和引用作者正确保留。该证据证明资料抵达及无程序禁言，不能证明真实模型已自然选择或理解正确。

完整数量、源码摘要与原生证据入口见[验证回执](verification/identity-grounding.json)。本轮没有增加第三方裁判模型、额外拆句调用或强制认人步骤；正式重载、手机 QQ 和真实模型补验仍分别登记。
