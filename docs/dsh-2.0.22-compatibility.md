# DSH 2.0.22-next 兼容补修

日期：2026-11-05。范围为 QQ 回复选择候选 `8a08043` 的后续宿主适配。所有本轮宿主测试使用隔离 SDK profile 和固定测试模型，真实模型调用为 0；正式人格、QQ 账号和现有真实模型样本没有被改写。本文件不替代真实模型自然度或手机 QQ 验收。

## 已确认的宿主变化

安装版本为 `dsh-desktop-next@2.0.22-next`，相关 SDK 为 `0.2.2-rc.1`，Cordis 为 4.1。最终复验的 app.asar SHA-256 为 `c525939eb23116128a22bf23a78b692abe7995f65ec5baf7b509ca1290262000`。先前同日的 C705 包与该包已检查的 404 份源文件逐字节一致，这不等于两份完整安装包相同。

新版在 `tools.resolve()` 中确定本轮工具集，随后才组装提示和进入 `agent/pre-step`。原来的异步人格挂载等待发生得太晚。会话先创建、再切入相续预设并立即发送消息时，首轮可能没有人格工具；普通 QQ 初始预设路径通过不能覆盖这一边界。

## 产品补修

1. `companion-scope.js` 在原生工具集捕获前等待当前相续 Agent 的既有挂载任务，保留原调用接收者与作用域。只匹配实际相续预设和当前准确 Agent 对象，可信 worker 和其他预设不发起人格挂载。多 scope 共用屏障，退出时恢复原属性；请求取消、挂载失败、同 ID Agent 替换、预设离开和 revision 更替均有回归覆盖。旧宿主的提示组装路径保留。
2. `instance-lifecycle.js` 精确把插件自己生成的 `host-delivery-facts.json` 纳入受管文本清除清单。此前该文件会被误判为未知文件而阻断清除。相邻未知文件仍阻断；预览只读、名字确认和现有清除流程保留。只在合成人格副本中验证了清除。

本轮没有改动 core、人格提示、人格决策协议、记忆取舍或回复策略。工具就绪等待只处理工程时序，不增加先调某工具、必须回答、固定聊天间隔或强制分条规则。

## 测试器适配

- 新宿主不接受 `tools.mode:"native"`，SDK 已提供原生执行器，六个测试 overlay 移除过时字段。
- 新 SDK 自带异步初始化的 connection 服务。onboarding/reflection 夹具复用它，旧 SDK 保留原有构造路径。
- 社交断言分别检查“适配器存在”和“账号未认证、未连接、能力未验证”，不再把两者混同。
- reflection 状态接口的连续读取可能横跨整理提交。稳定观察用读取起止的 runtime 版本比较，`waitPhase` 只接受版本一致的观察，不把期望记忆内容写入等待条件。首个失败的持久化记录显示修剪已成功提交，该失败作为测试器竞态保留。

## 与 QQ 真实模型测试的关系

ZCode 第二、三节的原始 28 次 provider 用量合计 344,125 tokens、零新增未知，分条能力与五个可比较场景的结果保留在原范围。其 AB-6 的引用步骤未进入模型，继续未评分；修正版驱动以入站 ID→claimed turn→助手消息 ID→送达事实关联，13 项离线检查通过。此测试器修复不算 AB-6 已通过。

正式加载和手机 QQ 收发仍需当前加载版本、监控 scope 与回滚回执；本轮兼容测试没有激活它们。详见机器可读的[本轮验证回执](verification/dsh-2.0.22-compatibility.json)。
