# Shared implementation contract

JavaScript ESM core has no DSH imports or external runtime dependency. The native UI client is generated from local ui sources by scripts/build-ui.mjs and shipped with the package. Authoritative behavior and schema: persona-memory/3 documents in plan/persona/. The core never decides personality content through hard rules.

Root owns adapter, package/scripts and docs. Storage writer owns core/store.js, core/repository.js, core/schema.js and test/storage.test.js, test/memory.test.js. Runtime writer owns core/runtime.js, core/prompts.js, core/index.js and test/runtime.test.js, test/autonomy.test.js. Agree exact methods with each other; all writers may read any files, do not overwrite another writer's files.

Expected generic Store API: new JsonStore(root,{fault?}); await open(); await readJson(path,fallback); await readLines(path); await transaction({runId,json:{path:value},jsonl:{path:records},expectedVersions?}); await close(). Recover incomplete prepared transactions idempotently, serial reads/writes, safe relative paths, process ownership lock, durable atomic replace; retain bounded journal. fault hook supports meaningful recovery tests. Do not import source application modules into verification scripts.

Expected repository port: new MemoryRepository({root,config,clock}); await open()/close(); ingest(ChatRecord-like input) -> {duplicate,record,eventId,gap?}; captureHot(HotRecord-like input); upsertPerson; assign; search(input,{personId?}); forget(input,{personId?}); introspect(input,{personId?}); getRuntime()/saveRuntime(); getPersona(); getContext({personId,query?}); prepareConsolidation({personId?,maxInputChars?}); applyConsolidation(run,patch); getCapacity(). Writers should coordinate complete signatures before consumer code. Method aliases are acceptable for adapter integration, but public behavior and schemas remain consistent.

Runtime port: new PersonaRuntime({repository,clock,model,host,config}); await open()/close(); accept(input,environment) records participant dialogue without requiring reply; decide(input,context) persists effective decision then executes via host; search/forget/introspect wrappers; compose(context) -> immutable snapshot; consolidate(context) via model port and repository batch; handleDue()/handleSignal(signal,context); stopProactive()/resumeProactive(). Model port takes {purpose,messages,...} and returns text or structured patch without direct credentials. Host port supplies delivery, request/clock scheduling and source access; tests use explicit injected fakes. Decide does not assess whether a personality opinion is correct.

DSH adapter will derive trusted sourceKind/content blocks, stable source IDs, environment/channel routing, and request scope from real host APIs. Unknown person can stage. Identification needs a personality-expressed control: allow optional identityPlan (new/associate/unknown with displayName/personId/source refs) in persona_decide; this is a technical expression of existing autonomous recognition, not authentication. Root will document this additive protocol clarification if needed.

No fixed 3s/10min, daily quota, silence penalty, proof-count gate, forced sleep, hard topic filter, commitment task executor, or immutable personality forever. Plan timing can use explicit timestamps or new_message/environment_change/explicit_wake. Sleep can wake by at_time/consolidation_complete/explicit_wake. Preserve currentDecision, event listeners, wakeRunId, outbox and source cursors across restart. A selected listen may wait indefinitely. Only selected observation channels are ingested; participant dialogue excludes runtime injections/agent notifications/tool blocks from C1, but temporary process context is separate.

Tests must cover actual meaningful failures: duplicate sources, assignment, cross-subject correct recall, selective hot consumption, fault between multi-file updates, natural eviction keeps summaries, explicit revocation persists after rebuild, independent request snapshots, partial control merges, timed vs event-only waiting, sleep silence/wake, cancellation/outbox ambiguity, two modes and bounded storage. Do not use an arbitrary count or acceptability rate as personality quality proof.
