# 形象档案、作品与可选图片／视频服务

版本0.10.0，修订日期2026-10-27。“创作”是五个主入口之一，形象档案、图片服务、视频服务、开始创作与作品任务分别进入子页，与共同人格共用实例，但图片／视频原文件和服务密钥分开存放。它提供稳定参考和实际创作接口，是否使用、怎样理解自己的形象仍由人格判断；用户可选择不开通服务。

## 0.8.0从目的进入创作

先在“创作 → 形象档案”保存描述与参考；需要开通时，再进入指定图片或视频服务填写配置。普通配置保存不等于生成。进入“开始创作”明确提交可能付费的生成请求，再到“作品与任务”查询、预览或下载；结果未知时继续查原任务，不重新付费提交。既有形象锁、服务默认关闭、实际参考能力、资产容量及权限规则不变。

0.8.0只重整管理界面的导航、内容层次与交互流程，core/、adapters/和运行时schema相对0.7.0未改，八个人格工具与persona-memory/3保持兼容。本版[完整本地回归](verification/0.8.0-tests.json)605/605通过，失败／取消／跳过均为0；UI与宿主专项55/55（50项UI＋5项host）属于同批验证，不另算独立需求。[真实DSH界面](verification/0.8.0-native-ui.json)完成5个主入口与16项任务式旅程、浅深主题及保存回读，使用隔离样本、无真实模型或平台调用。[后端兼容回执](verification/0.8.0-backend-compatibility.json)逐SHA核对50份后台及配套文件，继承0.7.0 SDK证据，未声称重新执行本版SDK。0.7.0的583/58/35与当时九页GUI保留历史含义；远程CI和发布状态另以实际结果为准。

## 建立与保存共同形象

填写形象描述，上传PNG／JPEG／WebP参考并设为主参考，可查看当前版本与小图预览。档案包含描述、primaryAssetId、locked、版本、更新时间与有限历史；主参考指向已核验类型与SHA的真实资产。清除主参考只解除选择，不自动删除作品。

“锁定形象档案”限制人格工具改描述、主参考和锁定状态，用户仍能在设置中修改。未锁定时人格可按需使用persona_media更新；没有按性格标签自动生成、每轮换形象或固定更新频率。默认生成沿用当前描述和主参考；如果服务没有配置参考图能力，明确拒绝，不静默忽略参考。相同参考可帮助连贯，实际一致性仍取决于所选模型／工作流，并非像素级保证。

## 开通图片或视频服务

图片与视频有各自开关，初值都关闭。只保存配置或打开设置不会生成作品。填入服务地址，密钥可写入或明确清除，永不回显；留空保留已有密钥。页面显示是否配置完整及实际接口能力。

| 类型 | 配置与实际行为 |
|---|---|
| OpenAI风格Images图片 | 填服务地址／模型，选择纯生成或支持参考图的edit；参考传输明确选JSON或multipart。JSON发images[].image_url，multipart发image[]；不在失败后自动换格式再付费发送 |
| ComfyUI图片 | 填实际ComfyUI地址，导入可运行的API工作流，并在高级项填写prompt节点／输入，参考节点／输入和输出节点 |
| ComfyUI视频 | 视频只提供此类型，必须配置真实视频工作流和输出节点；不凭一个URL／模型名假装已经具备视频能力 |

ComfyUI默认promptInput=text、referenceInput=image，节点必须对应用户自己的API工作流；前端不会猜模型列表、下载权重或替用户配置云端资源。跨域结果下载须显式配置允许的下载源，不把供应商密钥转发到另一个站点。公网服务需明确allowRemote并满足HTTPS与URL校验；本机／私网部署可用对应本地地址。

“连接测试”只探测连通与配置，返回verifiedGeneration:false，不发起作品生成或冒称模型可出图。服务的真实模型权限、计费、工作流与输出质量需用用户自己的配置验证。接口依据见[Images API](https://developers.openai.com/api/reference/resources/images)与[ComfyUI路由文档](https://docs.comfy.org/development/comfyui-server/comms_routes)。

## 生成、查询与平台发送

用户明确点生成时确认对应服务可能计费，先保存prepared任务并返回jobId，再执行请求。人格也可在用户开通后按需使用persona_media，无强制每轮调用；工具只提供有界描述、任务和资产元数据，不返回服务密钥或完整库字节。

任务区分prepared、running、submitted、completed、failed、unknown、cancelled与revoked。同一requestId回到原任务；媒体任务收据不自动淘汰，达到80条即明确拒绝新增生成，避免丢掉旧请求幂等身份后重复付费。删除作品只释放资产容量，不清除任务收据，也不会恢复生成任务名额；当前未提供任务收据清理／扩容入口。结果未知只查询，不自动重新提交。OpenAI风格任务后台完成；ComfyUI用原remoteJobId查询history和下载结果。重启遗留prepared／running转unknown，不自动付费重放；submitted只查询原远程任务。取消只处理本插件拥有的任务，ComfyUI不调用全局interrupt；远程已执行／计费或保留副本不能假称已撤销。

生成完成保存结果资产及参考版本，平台发送仍需persona_platform对已接入、支持且获许可的目标执行，取得自己的回执。作品完成不等于用户已收到，视频文件不等于视频通话。普通外发媒体还有渠道16MiB技术帽；本插件当前QQ OneBot11的record语音发送链单件另有8MiB硬帽。作品能保存在库中不表示该渠道能发送同尺寸文件。

## 作品库、下载、删除与备份

列表默认只读有限元数据，小图按需预览，不自动读整库或整段视频。大图／视频可单独下载：owner每块最多32768原始字节，宿主父桥检查同一资产／长度／顺序／SHA并合成完整文件，最多64MiB。iframe继续只allow-scripts；返回download_started表示已发起浏览器下载，用户仍可能需要处理浏览器下载提示。

当前主参考不能直接删除，先明确更换或解除。用户可明确删除非当前作品；若历史版本仍引用该图，清除这些图片引用并保留文字历史／referenceRemoved，回执返回clearedHistoryVersions。容量不足明确拒绝，不为腾空间偷偷删主图或旧作品。

身份档案在实例文本目录的identity/profile.json；默认作品库在该记忆根的同级`<根名>.media-assets`，生成配置在同级`<根名>.media-providers.json`。它们必须分开且不位于文本库内，不允许符号链接逃逸。文本备份只包含档案和文本，不包含外部作品、连接凭据或服务密钥。

“导出清单”仅导出xiangxu-media-export/1元数据、相对文件名与SHA，不复制图片／视频，也不含服务凭据。完整备份需另存清单引用的作品原文件；恢复到新环境后还要另行配置服务及连接。清单不能独自还原作品。

## 来源撤销与保真

人格生成／更新继承真实来源及参考依赖。明确遗忘会同步核心永久撤销：相关作业标revoked、禁止继续或重提，清除依赖该来源的资产和档案历史引用；读取／提交时也核永久撤销，防止迟到结果或恢复旧文本后复活。相同资产如同时有用户独立导入或明确确认的依据，可保留独立那一份，回执区分保留依据和实际本地清理结果。

本地文件无法清理、被修改或远程仍运行时如实报告，不把“已从可读索引撤销”冒称远程供应商／平台副本都被删除。删除、遗忘和实例变化会清理owner传输缓存。来源／SHA校验处理存储与执行可靠性，不审定人格应有何种外貌或性格。

## 当前技术容量

以下来自MEDIA_LIMITS及owner传输代码，MiB／KiB均按1024换算。它们分别控制二进制、元数据与请求；没有把库容量当成每轮模型输入量。

| 项目 | 当前上限 |
|---|---|
| 单张图片／单段视频 | 8MiB／64MiB；图片最长边8192、总像素33554432，验证PNG／JPEG／WebP与MP4／WebM容器 |
| 外部资产库 | 256个资产、原文件总256MiB；超限拒绝，用户明确删除释放 |
| 资产／任务元数据 | manifest 1MiB；作业收据最多80且终态也不自动淘汰，满后拒绝新任务；同时prepared／running／submitted最多8。删除作品不清任务收据 |
| 形象档案／历史 | 64KiB、描述2048个Unicode字符、最多8历史；达到字节帽先缩有限历史，当前档案不机械截断 |
| 独立来源 | 每条最多32源引用／64源记录、相同资产最多16份独立贡献；合并超限明确拒绝，不静默丢依赖 |
| 预览 | 图片最多512KiB且最多4194304像素；视频／超限仅元数据和单独下载 |
| Provider协议 | 工作流131072字节、响应24MiB、prompt8000字符、请求120秒、单任务最多4结果；owner表单仍受通用64KiB请求帽，过大工作流需先在服务端简化，不能抬高通用载体或截断后保存 |
| owner上传 | 仅PNG／JPEG／WebP，单文件8MiB，32768字节分块；最多2个未完成上传、5分钟过期，完成回执最多16条／5分钟 |
| owner下载缓存 | 单资产最多64MiB、保留60秒；完整同SHA检查，显式删除／遗忘会清缓存 |
| 通用owner载体 | 单请求64KiB、响应2MiB，原记忆明细仍按128KiB／分页读取；媒体文件不扩大这些帽 |

模型通过persona_media按需查询，资产页／任务页与工具结果片段游标分别使用；不将API工作流、密钥、整份图库或视频字节注入每次聊天。核心长期文本、近期、临时过程、动态上下文和整理预算仍见[唯一字段契约](plan/persona/persona-schema.md)。

## 与自主委派及任务档案的关系

当前人格工具共八个，新增persona_task供人格自主处理工程／研究等任务；persona_media仍是形象和图片／视频生成入口。worker的工程过程与完整报告保存在独立任务档案，主会话按需回收并自主retain；创建worker不会自动生成图片、更新形象或扩大平台许可。工程任务档案与媒体作品库相互独立，任务资料扩容不会改变媒体80条生成收据的容量。完整职责与保真边界见[自主委派与任务档案](delegation-and-task-archives.md)。

## 0.10.0 与平台媒体、翻唱的关系

形象档案与可选图片／视频服务继续走persona_media；QQ／B站操作走persona_platform，工具总数仍为八个。收到真实图片并成功附加给视觉模型，不表示已确认理解；B站故事板只代表实际采样覆盖。已有形象参考也不能保证每张生成结果完全相同。

翻唱是独立、自备、默认不开通的音频协议服务，不是图片／视频供应商或普通TTS的附带承诺。音频先经分块、SHA与容器检查登记，再提交真实作业、查询与保存产物；完整音频在库外有界资产目录，受管作业状态在实例内。语音发送仍需渠道支持和用户许可。清除人格文本不删除这些外部音频原件，也不撤销供应商远端副本；明确来源遗忘另沿来源撤销链处理。完整接口与容量见[0.10.0 接入与检索说明](integrations-and-retrieval.md)，未配置服务不宣称已生成或真实发出。

音频库单件16MiB与QQ语音发送8MiB是不同层的容量。WAV／FLAC／Ogg／MP3容器通过校验只支持对应入库与下载，不保证桥／平台接受该编码，更不代表音频质量或播放验证通过；发送仍取决于实际桥能力、平台限制和回执。
