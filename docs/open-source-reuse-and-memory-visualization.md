# 成熟接入复用与真实记忆可视化

核查日期2026-10-29。这是本轮研究与建议，不是新增功能验收。0.13.4只补QQ恢复启动与相处页连接提示；没有安装第二套机器人、迁移记忆后端或交付图功能。当前补修状态见[QQ登录恢复](qq-login-recovery.md)。

## 社交接入：已复用什么，下一步借鉴什么

QQ底层已经使用官方NapCat与OneBot接口，没有自行重写QQ网络协议。B站适配的`BILIBILI_SOURCES`也已注明参考`dsh-bili-scroll`公开实现；当前为独立JavaScript实现，不能把参考项目的功能列表当作相续已经全部接通。

| 项目 | 有意义的复用方向 | 对相续的选择与边界 |
|---|---|---|
| [NapCatQQ](https://github.com/NapNeko/NapCatQQ) | QQ协议、OneBot、登录状态与官方启动快登 | 继续使用现有外部桥。当前固定受管版本为v4.18.41；平台登录态失效仍需本人扫码，不复制重做QQ协议。 |
| [dsh-aurabot-qq](https://github.com/accomplish07zrh-eng/dsh-aurabot-qq) | 最接近DSH环境的会话绑定、媒体／引用／表情处理、模块边界和模型选择 | 对照其[模块接口](https://github.com/accomplish07zrh-eng/dsh-aurabot-qq/blob/main/src/modules/API.md)与消息中枢，按需借鉴接线；不叠加其自带人格、记忆或群聊策略。QQ空间等仍依赖实际模块和账号能力。 |
| [dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll) | B站扫码、资料／字幕／评论接口、投递回执与脱敏诊断 | 已有参考，可继续评估独立协议组件复用，减少重复跟随网站变化；不照搬刷站周期、人设或评论判断。 |
| [AstrBot](https://github.com/AstrBotDevs/AstrBot) | 多平台适配、扫码表单、媒体和消息链路追踪 | 多平台独立网关候选；先借鉴[消息追踪设计](https://github.com/AstrBotDevs/AstrBot/pull/10614)的容量、分页和恢复，再验证薄适配。不能同时让两套人格／模型自动回复器接管同一账号。 |
| [NoneBot2](https://github.com/nonebot/nonebot2) | 异步事件、协议适配与处理插槽 | 需要更纯粹消息网关时的备选，较少与人格核心重叠，但仍增加Python服务与部署维护；仅为当前QQ故障换框架没有必要。 |

消息状态值得统一呈现为“收到来信 → 已保存 → 进入模型 → 工具完成／失败 → 生成或决定等待 → 平台确认送达／未知”。每一步必须依据真实事件；没有自主决定的证据时，不能猜测人格不愿回应。技术诊断独立于人格记忆，其容量清理不能删除人格原件。

微信等平台不能承诺“全部权限”。例如[AstrBot微信扫码文档](https://github.com/AstrBotDevs/AstrBot/blob/master/docs/zh/platform/weixin_oc.md)的所列收发能力，不能推出普通微信群、朋友圈、头像修改或实时通话全部可用。接入、驱动支持、用户授权和真实验收继续分别显示，未测平台仍标未测试。

许可证也要分清：Aurabot、bili-scroll与NoneBot2在本次核查中为MIT；AstrBot为AGPL-3.0；[NapCat许可](https://github.com/NapNeko/NapCatQQ/blob/main/LICENSE)含限制性混合条款，不能按MIT随意复制内核。调用独立服务、参考设计与复制分发源码是不同做法，实际采用代码时应核对应固定版本及保留必要许可。未找到可确认的`dafeiyu-config-pack`官方仓库，不采用相似名称项目冒充。

## 视频里的图能说明什么

用户提供的视频约33.6秒，代表帧可见彩色节点、连线与类别。它证明存在某种关系可视化界面，不能凭画面证明背后真实采用神经元学习、更新了大模型参数、产生了意识，或比现有检索更准确。数据关系图、算法索引与模型内部神经网络是不同层次。

相续可以做真实的“记忆关联图”：让用户看懂这段经历涉及谁、来自哪次交流、怎样关联另一段记忆，以及人格后来如何重释。图形承担查找与解释，不替人格决定回忆、情绪、重要程度或成长。

## 现有记忆已经能提供的基础

统一时间线保存稳定编号、原话、发生与记录时间，并允许人格补充标题、前因、经过、结果、细节、当时感受和现在理解；短期、长期与归档是同一原件的转层。普通记忆、深刻经历、人物、编码、来源、显式关联、替代旧理解等已有数据可以成为不同节点与有名称的边。

检索已有文字匹配、可选语义与显式关系遍历，并返回命中词、关联路径和有效时间。当前界面“为什么找到这一条”仍偏技术JSON，先翻译成可读说明就能提升可用性，无需先更换记忆系统。提供过参考不等于人格一定回忆或采纳，界面必须保留这个区别。[现有时间线与上下文说明](memory-timeline-and-context.md)

## 推荐的第一版，而非已实现清单

1. 在“记忆”中提供“列表／关联图／时间线”，默认保留易读列表，继续跟随DSH主题。
2. 从选中记忆或搜索结果开始，展开一层实际关系，按人物、时间、类型和存储层筛选；标注本次展示量和未展开量。点击节点看侧栏，再按需读完整原件和来源。
3. 每条线说明“来源于”“提到人物”“明确关联”“替代旧理解”或“展开编码”。算法相似另用虚线和具体标记，不冒充人格建立的关系；没有关系时允许孤点。
4. 如高亮本次检索或组装给过的材料，只称“本次提供的参考”，不画成真实脑活动、已回忆或情绪热度。浏览图不自动增加模型调用或改变记忆。
5. 先做有界二维图：按选择加载局部、停止持续布局、隐藏暂停、离开销毁。显示上限只限制当前视图，不能因此丢弃原件或限制人格记忆量。保留列表与键盘操作。

优先评估[Cytoscape.js](https://js.cytoscape.org/#introduction)：纯JS关系图展示与交互，核心及官方扩展MIT许可，适合现有页面。[force-graph](https://github.com/vasturiano/force-graph)是简单Canvas点线图备选。渲染库负责画实际数据，不负责制造记忆或人格。

大库性能仍需单独处理：当前检索先扫描所选本地资料再筛选／分页，前端只画100个节点不代表后端只读100条。需要有界图查询投影，必要时建设可重建本地索引与增量读取；不能仅加动画就宣称效率改善。图缓存、导出、来源展开与旧备份仍遵循既有遗忘与撤销，不跨人格实例混图，也不从旧缓存复活遗忘内容。

## 记忆项目可以借鉴，但现在不必迁移

[Graphiti](https://github.com/getzep/graphiti#readme)值得借鉴时间有效范围、来源追溯与混合检索。整体引入需Python、图数据库、模型／向量服务和外围运行层；自动抽取不能覆盖相续原件或替人格裁定意义。现有规模是否需要该后端，应以读取量、延迟和资源测量决定。

[Letta memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks)与[archival memory](https://docs.letta.com/v1-sdk/memory/archival-memory)的核心常驻、详细档案经工具检索，以及整理知识与原始历史分开的思路，与相续当前设计相近，可借鉴说明与操作方式。

[Mem0当前OSS迁移说明](https://docs.mem0.ai/migration/oss-v2-to-v3)明确图记忆转为Platform内建功能，OSS移除外部图存储集成；旧教程不能当成当前开源版能力。[Platform图记忆](https://docs.mem0.ai/platform/features/graph-memory)也不能冒称免费本地组件。暂不因此新增托管依赖或迁移。

建议顺序为：稳定现有收发和故障提示，改善来源与检索解释，再实现真实二维关联图；只有实际规模证明需要时再替换索引后端。所有社交对象、发言、记忆取舍、资料内容、情绪理解和成长仍由人格自己决定。
