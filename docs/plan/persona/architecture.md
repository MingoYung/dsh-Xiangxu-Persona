# 长期 AI 人格插件：实施架构

当前实现（0.4.1）：产品名`dsh-Xiangxu-Persona`，包名`dsh-xiangxu-persona`，预设展示名“相续人格”；内部presetId `persona-memory`与数据契约`persona-memory/3`保留兼容。原生设置保留七页功能并沿用DSH宿主颜色、字体和透明背景；主动联系开关附日常说明，休息时才显示“现在叫醒”。QQ/微信已有兼容桥的高级配置默认折叠，真实使用仍需用户已有桥和账号，尚未实现扫码或接管桌面登录；Windows本机声音入口保留。当前实现及证据见[管理界面与验收](../../management-ui.md)与[渠道接入](../../channel-integration.md)。研究和旧版本数字保留各自历史范围，不提升为本版验收。

版本：`persona-memory/3`。本次修订日期：2026-10-26。字段、枚举、控制决定与引用结构的唯一权威为 [persona-schema.md](persona-schema.md)；本文规定生产、消费、交付和故障恢复顺序。宿主能力的既有证据与未核项目见 [api-surface.md](api-surface.md)，不能把设计伪代码当成已实测 API。

## 1. 产品边界与执行边界

这是同一个 AI 人格认识多个对象的系统。与某人的经历可以改变共同人格，继而影响它面对其他人的方式。按对象组织数据用于认清归属、找到材料、解释经历；它不是多租户权限系统。正确谈论第三人是正常能力，检索与提示词必须保留材料真正说的是谁，不能把 A 的经历写成 B 的经历。

人格决定注意谁、记什么、是否检索、回不回、话是否说完、等多久、说什么、下次何时再看、睡不睡及睡多久，也决定如何理解印象、承诺与边界。程序负责把已作出的决定可靠地执行，并报告实际做到了什么。时间、未回应、存储积压、对方原话可以成为判断材料，不能暗中转成发送次数、最短间隔、沉默退避、固定轮询或强制睡觉的规则。

聊天材料和工具结果可以影响人格的理解，但不直接成为文件写入指令。模型通过固定控制接口和结构化变更提出决定，程序只检验数据结构、稳定引用、目标解析、版本和执行状态。印象允许主观、有偏差、慢慢改变；字段校验不负责裁定这种印象是否正确。

锚点是身份基调，不随每轮动态内容改写；梳理可以让它慢慢变化，保留有限历史便于回退。人格、关系材料和记忆不是越多越好，预算按整个实例计算，数量不是人格成立的资格。

## 2. 存储职责与物理布局

存储按职责分五族：C1 原始聊天、C2 检索派生、C3 共同人格、C4 运行态、C5 诊断；H1 是供本轮梳理使用的临时过程区。对象还有九个逻辑分区 P0–P8，职责见 [relation-model.md](relation-model.md)。P7 承诺材料放在印象经历内，P8 边界材料放在 C3 facets 内，不要求独立文件。

建议布局如下。分段、journal、manifest 和有界诊断的实际文件数可随实现调整，不以固定文件数量验收。

```text
$DSH_HOME/persona/
├── config.json                       # PersonaConfig
├── registry.json                     # RouteBinding / AssignmentRecord 索引
├── self/
│   ├── persona.json                  # C3 PersonaDocument，含 P8
│   └── history/                      # 有界人格旧版本
├── global/
│   ├── index.json                    # scope:global 的共同检索材料
│   ├── codes.json                    # scope:global 的共同编码
│   ├── state.json                    # C4 RuntimeState
│   ├── snapshots.jsonl               # C5 RequestSnapshot，滚动有界
│   ├── outbox.jsonl                  # OutboxRecord 与交付状态
│   └── revocations.jsonl             # 明确纠正/遗忘，支持 checkpoint 压缩
├── journal/
│   ├── intake.jsonl                  # 有界接收元数据、稳定 eventId、源游标
│   └── runs/                         # 未提交 run 与近期 manifest，有界清理
├── staging/
│   ├── events.jsonl                  # personId:null 的未归属源事件
│   └── hot.jsonl                     # 未归属临时过程/原件引用
└── people/<personId>/
    ├── identity.json                 # P0
    ├── impression.json               # P1，含 P7 承诺经历
    ├── index.json                    # P2
    ├── shortterm.jsonl               # P3
    ├── codes.json                    # P4
    ├── state.json                    # P5
    ├── pending.json                  # P6 暂存解释，可被人格使用
    ├── stream.jsonl                  # C1 有限原始聊天；活动段追加/可轮转
    └── hot.jsonl                     # H1 本轮梳理工作区
```

根目录沿用既有插件习惯：`process.env.DSH_HOME || join(homedir(), '.dsh')`。部署确认实际 profile 与实例根目录，不能让两个互不知情的写者共用文件。文件路径由内部键构造，模型产生的自由文本不拼接成任意路径。

每条对象记录都带 personId；全局记录用 `scope:global`、`personId:null`。归属未明的事件进入 staging，确认后用 assignment 事件派生视图，不复制根事件、也不重复累计经历。scope 表示用途和主体，不代表访问权限。对象键与通道键分开，sessionId 只定位会话。

所有概括、印象和检索条目通过 `srcRefs` 追到宿主源事件，统一使用 `sourceSessionId/sourceEventId`。role、origin、epistemic 与 kind 都沿用 schema 的唯一枚举；“谁说的”“主动还是被动”“自述还是理解”分开表达，不能混成一个 source 字段。

C1 不永久无限增长。活动段以追加方式接收，随后可分段轮转、自然淘汰或按明确遗忘清除。索引损坏可从仍可用来源与已提交概括重建；不能承诺有限来源能完整重算全部历史人格。人格决定、梳理结果、纠正与撤销本身也是需要保留的状态，不能假装它们都是原始聊天的确定性函数。

## 3. 容量、时间与上下文预算

以下为工程初始值，不是人格行为规则。

| 配置 | 初始值 | 口径 |
|---|---:|---|
| `schemaVersion` | `persona-memory/3` | 持久格式版本 |
| `longTermTargetChars` | 1000000 | 整个实例持久记忆文本总目标，含 C1/C2/C3/P1/P4 等，不按人数倍增 |
| `recentTargetChars` | 100000 | 当前对象近期读取目标及近期视图容量候选 |
| `recentPreferredDays` | 3 | 优先覆盖的近期跨度，超量时交人格梳理取舍，不保证全部必留 |
| `tempTargetChars` | 200000 | 整个实例临时过程缓存候选，不按对象倍增 |
| `diskReserveBytes` | 部署时配置 | 实际磁盘安全余量，以 bytes 监测 |
| `consolidationMode` | `sleep` | 用户可选择 `sleep` 或 `on_write` |

统计文本目标和实际磁盘 bytes 两套口径。JSON 元数据、宿主日志、journal、物化视图、副本、备份和诊断的 bytes 另记，不能把“100 万字”宣传成硬盘只占对应字节。近期视图是派生数据，不代表新增一份事实；实际重复文本仍消耗空间。备份和诊断滚动有界，journal 在可恢复前提下做检查点和压缩。

超临时目标时先把后续完整过程保存在宿主可用来源中，以有界 host-trace 指针导航，按需分页读取。到实际安全容量边界可暂停插件新增冗余副本，报告 memory_gap 与回补游标，正常聊天继续。宿主原件不可读就如实记录缺口；不承诺零损失，不因容量强制人格睡觉，也不说“它已经决定睡”。

时间统一采用 epoch ms 与 IANA timezone。区分源事件发生时间与 observedAt；每次决定取同一个 now 并随请求快照传递。时区变化、机器休眠和时钟跳变在恢复时重新计算到期任务，不能依靠上一次进程内计时器的剩余毫秒。时间流逝本身是新事实；人格选择了定时复查时，到点即使无新消息也重新判断。只选择事件型 listen 时保持监听，不强迫周期唤起。

S0–S5 初始总上限 2,970 tokens，S6 宿主历史另计。统一 tokenizer；输出预留、工具定义和宿主历史一起纳入模型实际窗口计算，不按固定中文字数估算。材料少时可以少注入，不要求填满。

| 段 | 内容 | 初始上限 |
|---|---|---:|
| S0 | 当前对象、真实主体、通道环境、时间及正在执行的决定 | 120 |
| S1 | 当前版本锚点 | 200 |
| S2 | 人格描述：axes、facets、signatures 的相关材料 | 700 |
| S3 | 当前相关习惯 | 150 |
| S4 | 关系、印象、承诺和边界等判断材料 | 300 |
| S5 | 人格选择检索后取得的片段 | 1500 |
| S6 | 宿主对话历史 | 随宿主窗口计算 |

边界是人格判断材料，不做全量禁忌扫描、never_mention 强拦截或生成后审查。承诺可以记录时间、原话和做过什么，程序不把“未履行”当任务失败。人格可以改变对两者的理解，变更保留来源和版本。

## 4. 从宿主事件到人格决定

### 4.1 环境、身份与注意范围

环境适配器采集真实可用的平台、房间、显示名、头像、通道与时间线索；视觉另留适配接口。适配器只声明实际拿得到的字段，不假定 DSH SessionHeader 有用户身份或任意路由模型支持可用视觉。既有取证显示 SessionHeader 没有 user/owner 字段，详见 api-surface。

先给人格环境和已知对象线索，由人格形成“是谁、在什么场合、我注意谁”的判断，再把结果用于存储路由。昵称、头像、同一 session 都不是自动认证；未知可暂存为未归属，也可沿用仍适用的既有判断，不强制确认、不一律新建人。发现错认时以 assignment 更正派生归属，源事件不变。

单聊、群聊或多个通道都保留真实发言者。V1 可先落单聊，但适配器取不到群聊 speaker 时明确未知，不能把多人合成一个人。跨对象检索保留真实主体及来源说明；归属准确性校验用于发现路径或内容写错，不阻止合理谈及第三人。

### 4.2 接收与回复分开

接收范围由人格已选注意范围与通道事实决定。范围内已接收的事件先记录，再决定是否回复；“暂时不回”“继续等”“睡着”都不能成为丢弃已接收消息的理由。不是让插件偷看全部来源；人格改变注意范围后，适配器按新决定订阅或消费。

接收流程：

1. 取得稳定宿主 `sourceSessionId/sourceEventId`、源时间与 observedAt，检查宿主 source.kind、实际来源及内容块，识别真正参与者的对话正文。user/message 也可能装运行态注入或代理通知，不能仅凭 type/role 当成真人发言；runtime-context、agent-instructions、插件状态卡、agent-message、工具与思考不进 C1，不算人物经历，可按需作诊断或临时过程。混合内容逐块分类，不能把真人正文与注入一起全收或全丢。ChatRecord.sourceKind 保留归一后的真实来源，contentClass 固定为 participant_dialogue；HotRecord 的来源与 kind 沿用 schema。assistant 只投影真实外显文本。具体来源字段、流式增量与最终事件映射在 P0 实测后固定。
2. 查接收去重索引；同一根事件的重放、重试、摘要或再次梳理只计一次。fork、编辑、撤销和日志重放不能仅凭 turn 数判断新经历，保留原事件 lineage。
3. 写入接收 journal，得到插件有序 eventId。归属未知写 staging；已知写对应 C1 及必要 H1/引用，然后推进 ingestCursors。
4. 异步维护近期视图与检索派生。原文自然淘汰后可保留重要概括和来源摘要，srcRefs 标 available:false。
5. 把新事实和已到期决定交给人格处理。是否回复、是否检索、是否等待以及等待多久由人格决定；本地规则只提供线索，不设置固定 3 秒或最大等候期限。

源事件 ID 不稳定、读取失败或 C1 写失败时，不伪造“已完整记住”。保留 memory_gap/回补位置；不把该事件的派生更新提交成完整状态，之后由可用宿主来源补齐。若来源已不可恢复，缺口继续可见，聊天不因此中断。

### 4.3 人格控制接口

固定注册 `persona_decide({attention?,replyPlan?,nextCheckAt?,sleepPlan?,retrievePlan?})`，由当前宿主执行上下文补缺省对象与通道。字段结构及决定记录见 persona-schema；工具是人格表达决定的接口，不是外部裁判。

人格可在正常回复轮次同时作决定，也可在必要时单独判断。采集、排队、去重和本地索引打分不调 LLM；人格判断本身可能调用模型，所以不承诺每轮零额外调用。没有决定就保留“未决定”，不能用默认沉默当人格选择；首次需要人格判断的时点由启动/通道接收流程触发，随后按它写下的时间或 recheckOn 事件条件继续。

承诺、边界、暂存解释都可供人格考虑，不设证据数或置信度门槛。已回应、未回应、明确拒绝是不同事实，交梳理自主解释；不因 ai_initiated 来源降权，不因沉默自动降低重要度。

## 5. 检索与请求作用域注入

检索计划由人格选择，可复用先前仍适用的决定或在当前轮次经 memory_search 取材。关键词、bigram、实体线索和本地评分可以降低寻找成本，不得把“输入短于 30 字”“没有上次一词”变成禁止检索的硬闸门。检索异常可返回明确不可用状态，由人格决定如何回应。

同一请求建立不可变 RequestSnapshot，至少固定 requestId、sessionId、personId、personaVersion、relationVersion、environmentVersion；未知对象明确为 null。组合 S0–S5 时所有材料来自该快照，跨对象条目保留主体。请求发送前后变更只影响下一请求，不污染已冻结请求。

禁止用插件全局 lastText、currentPersonId 或全局 disposer 储存“这次对谁说话”的动态文本。静态人格段可按宿主能力复用；动态段必须进入经 P0 核实的 agent/session/request 作用域。若 section API 不能提供所需作用域，改用宿主实际支持的请求上下文入口；在确认前此项是接入阻塞项，不能声称分目录已保证最终请求归属准确。

缓存处理看实际路由 systemPromptUpdate。既有取证中 in-history 表示同一请求序列内将变化提示追加在缓存历史后；未声明时可能重写首个系统节点。稳定内容在前、动态内容在后通常有利于缓存，但不应为节约缓存隐藏现在几点。S0 的实际位置按宿主语义与实测选择；每轮整体内容变化、工具定义、输出预留和历史增长都计入真实费用。不能同时声称 S0 每轮必变又声称仅靠“文本未变不刷新”保住前缀。

C5 记录冻结后的实际请求材料、版本、token 数与引用，按 requestId 定位。有界保留意味着旧诊断可能过期，不能对任意很久以前的回复保证完整解释。诊断可读不等于它是人格的完整心理因果。

## 6. 两种增量梳理模式

`sleep` 是默认的睡眠整理使用方式；人格仍需选择本次整理工作。`on_write` 合并呈现写入后的整理机会，复用正常对话让人格判断是否必要，不再每写一条自动发起付费整理。`consolidationPlan.run` 是一次性所选增量，`defer` 暂缓；清醒时也可整理。两模式沿用来源和提交游标，不重放旧经历。

on_write 合并的是整理机会，不是按固定时间窗自动派发模型；人格选择 run 后才启动有界增量，合并不是回话时限。前台聊天不等待后台整理完成；人格更新在下一次已提交版本生效。模型资源不足导致后台积压就如实呈现，不暗中改成强迫睡眠。

### 6.1 本轮可用的完整临时上下文

C1 长期只保存聊天正文，不长期留 reasoning 全文。H1 为本次整理保留可用完整对话、思考与工具原件，分两类：已缓存原文、指向宿主原件的 host-trace 引用。摘要可以做导航，不能把一行摘要称为完整上下文。

assistant-stream、tool/result 等钩子是否含可读取 reasoning/完整工具原件、如何对应 sourceEventId、日志压缩格式与分页读取，均在 P0 验证。模型或宿主未暴露的内容不能恢复；缺源与截断显式标注，不能编造“当时为什么这样想”。按游标分页选材，逐批处理，不把 20 万字缓存或整个宿主日志一次塞给 LLM。

### 6.2 可恢复提交协议

单写者负责同一实例的持久变更；多实例争用同一根目录时先获得实际进程锁/租约，不只在文档里假定不会发生。临时文件加 rename 只保证单文件替换，跨文件更新由 journal/manifest 协调。

每个 ConsolidationRun 使用 schema 中的 runId、inputEndEventId、inputVersions、validatedPatch、commitMarker、status、consumedHotRefs 和前后游标：

1. 固定本轮输入高水位及版本；晚到事件留到下一批。读取人格可用材料与完整临时上下文分页，不按固定支持数裁定能否产生印象。
2. LLM 返回结构化 patch，可以更新记忆概括、共同人格、印象、编码和暂存解释。源角色与 epistemic 保留，理解不冒充用户原话。模型不能直接执行任意文件操作。
3. 验证 schema、内部引用、真实主体、输入版本及容量。版本冲突重取最新状态再协调；尤其两个人的梳理共享 C3，不能后写覆盖前写。跨人的经历可以影响同一个人格，不把一次调用按人拆分当成身份隔离原则。
4. 写候选文件与 run manifest，完成必要持久化；生成 commitMarker，使读者只看到完整已提交 generation。重试同一个 run 不重复累计根事件或支持记录。
5. 全部提交后推进 consolidationCursors，最后仅清除 consumedHotRefs 对应的已消费前缀。整理期间新追加的 H1 不删除；超单批的积压继续下一批。
6. 失败保留未消费来源与可恢复状态；执行层可以重试传输/落盘故障并记录重试费用，不自动替人格决定“再睡多久”或改变性格。无法恢复的缺口写 memoryGaps。

回滚选择有限历史人格版本并产生新提交，不把旧版本号倒写成当前；保留回滚原因与对后续派生的处理。自然巩固可以沿用旧理解，但重试、再次摘要和回滚不能制造新根证据。

## 7. 睡眠、调度与醒来

人格用 sleepPlan 表达入睡及唤醒条件，用 nextCheckAt/replyAt 或 replyPlan.recheckOn 表达重新判断。调度器恢复人格指定的时间和事件监听，卸载时清理；没有固定 10 分钟心跳替人格决定检查频率。到期或选定事件发生表示执行先前决定的再判断或唤醒，不等于自动发消息。listen 可以只等新消息、环境变化或明确唤醒，不必安排墙钟时点。

sleep.state 与 activeRunId 分开：睡眠是人格业务状态，梳理执行锁属于进程状态。LLM 整理完成不一定等于人格选择醒来，执行异常也不能把 sleeping 永久变成一个无人处理的锁。SleepPlan.wakeCondition 由人格选择 at_time、consolidation_complete 或 explicit_wake；只有选择 at_time 才要求有效 wakeAt。wait/listen 可只给 recheckOn 事件条件，不强迫时点；有定时计划才校验 replyAt/nextCheckAt。无限观察是可执行事件监听，不能当成结构错误。确实无法解析的决定返回具体执行信息错误，不由程序任意填作息或间隔。选择整理完成后醒时，以 RuntimeState.sleep.wakeJobId 关联所选作业及全部子run，全部提交后才触发，不因其他批次完成误醒；旧prepared run保留原wakeRunId兼容；空增量可完成，失败不能假称完成。

sleeping 期间禁止 assistant 输出。所选择观察范围内到达的消息继续持久排队，按 personId、speaker、channelId/sessionId 保留原文。不能只用一个全局“来了几次”的计数替代不同人的来信。

醒来时一次接收汇总，指向各对象/通道的 pending 和原文；多人内容不合并成同一人的发言。人格再决定回谁、回什么、是否检索和下次何时看。汇总被持久接收与具体消息交付分别确认，不能刚往 inbox 塞一条注记就清空全部 pending。

agent/pre-step 的 reject 是否重试、是否消费 inbox、会否显示错误、能否仅抑制待生成轮次，仍待 P0 贯通测试。如果不是合适入口，使用宿主实际提供的排队/暂停机制实现睡眠语义，不在未核钩子上许诺“发了消息不会回复、醒来必回一次”。

## 8. 主动交付与用户停止

主动表达沿用人格的 attention、replyPlan 与 nextCheckAt 决定，最近互动、未回应和经过多久都是判断材料，不设次数上限、最短间隔或沉默退避。人格选择了定时复查时，程序到期执行决定并取得当前事实，不用旧的“先不说”跳过这次复查；只选事件型监听则继续等待相应事件。

交付链路分五步：

1. 根据环境路由解析目标 `{channelId,sessionId,personId}`，同一对象多通道时由人格/当前决定明确目标。agent 已销毁、会话关闭、目标歧义都返回可见执行状态，不随便换人或换通道。
2. 创建稳定 deliveryId 和 outbox 记录；把“准备判断”“准备生成”“已入队”“真实交付”分开。生成材料与已生成正文如何传入 inbox 必须符合实际宿主语义，不能先生成 40 字再让 agent 随意二次改写却把原文本记成已发送。
3. 经核实的宿主入口提交，保存 inbox/请求关联。inbox.append 只证明排队；是否启动 idle agent、是否需要唤醒、surface 是否可见，都由 P0 证实。
4. 用真实 assistant 源事件及通道交付确认结算，写 origin:ai_initiated 的已发正文与 srcRefs；不在 append 返回时假记“已经说过”。宿主没有终端送达回执时区分“宿主已输出”和“用户已收到”。
5. 重启按 deliveryId 查已知交付与宿主事件，不重复生成/发送。确认状态不明时先核对，无法核对则保留 unknown，不能同时承诺任意故障下 exactly-once 送达。

用户明确要求停止主动时，急停表示执行这项用户意图：取消未交付 outbox、未领取队列和待生成主动工作；发送前检查同一停止状态。已开始的请求按宿主实际取消能力处理，不能以“下次 tick 才生效”敷衍。已实际交付的消息无法撤回则如实说明。此开关不是人格频控，不替代它平时的主动判断；普通用户输入与被动回复是否继续以用户这次停止范围为准。

## 9. 纠正、自然遗忘与明确遗忘

自然淘汰与语义撤回分开。有限原文被轮转时，重要概括仍可留下，srcRefs.available:false 和来源摘要说明已无法展开；不能因所有原文离开近期窗口就级联销毁所有概括与性格经历。

用户明确纠正或 memory_forget 产生独立撤销记录，重建、检索、概括和编码消费时都应用撤销，避免从宿主旧日志重新读回后复活。忘记目标先解析清楚；对象不明时不批量删除，已知他人可作为显式目标，不默认管理员 ACL。忘记一段、忘记某人的材料与删除全部人格不是同一个操作。

本地清除范围涵盖原文、热区、索引、近期视图、概括、快照和可定位的引用；关联人格/印象由梳理处理来源撤回影响，不能仅删索引却保留同义概括继续命中。撤销账本保存阻止复活所需的最小定位信息。宿主持久日志、外部通道和独立备份是否清除需要对应能力与实际操作，本插件不能假称已擦除所有来源。

## 10. 启动、迁移与故障恢复

完整有效决定保存在 `global/state.json` 的 `RuntimeState.currentDecision`，注意范围、带目标的回复计划与检索计划不能只留在进程内。控制输入按Schema合并为完整当前快照，与派生sleep/schedule一起提交；新子计划替换其旧内部条件，回执显示仍有效的计划，旧决定仅有界诊断。

启动顺序：确认实例根目录与写者锁 → 校验 schemaVersion → 恢复 journal 已提交 generation / 未提交 run → 恢复接收去重及缺口游标 → 读取currentDecision并恢复attention、replyPlan、retrievePlan及sleep/schedule → 核对pending/outbox与宿主事件 → 重建定时器、recheckOn事件订阅及wakeCondition对应唤醒监听。进程锁失效不等于人格醒来，旧activeRunId也不能永久阻塞新进程。

格式迁移使用有限备份、候选目录、校验及一次提交；保留源事件 ID 与撤销记录。未知高版本只暂停相关记忆写入并报告，正常聊天继续；不以“读不了就删掉重建”覆盖无法复原的人格与决定。

对故障分别给出状态：源不可读形成 memory_gap；检索不可用返回明确状态；模型调用失败保留待执行决定与费用；磁盘不足暂停冗余副本；交付不确定保留 outbox unknown；某个派生文件损坏只重建可重建部分。不用一个全局 muted 或 asleep 代替所有故障状态。

## 11. 工具、模块与费用

工具一次稳定注册，具体字段见 persona-schema：

- `memory_search({query,targetPersonId?,scope?,limit?})`：人格主动取材，可指已知第三人，结果保留真实主体。
- `memory_forget({ids?,targetPersonId?,before?,reason})`：明确纠正/遗忘的执行入口，解析清楚目标并记录撤销。
- `persona_introspect({targetPersonId?,section?})`：读取当前人格、关系材料、决定与可用来源说明。
- `persona_decide({attention?,replyPlan?,nextCheckAt?,sleepPlan?,retrievePlan?})`：提交人格自己的决定，并返回实际执行状态。

建议模块按环境适配、接收去重、有限存储、检索、请求快照、人格决定、梳理事务、睡眠调度、交付与诊断分开。宿主 API 封装在适配层，未核返回值不扩散到业务模块。现有 dsh-persona 可承载部署底稿，但应明确与 C3 anchor 的合成/版本关系，不保留两份各自漂移的身份权威。

费用分别计判断、梳理、重试、对话生成，以及 prompt 增量、缓存命中与失效。按实际使用模型和路由读取用量，不写“每天后台固定 ≤6 次”。如果只拿每 10 分钟独立判断作成本示例，8 小时是 48 次、全天是 144 次，即使全部决定不发也收费；该示例不构成调度规范。多对象可能共享一次人格判断，也可能需分别取材，按实测量化，不把对象数直接等同固定调用数。

## 12. 接入验收与待核边界

功能全上，阶段只安排施工先后。P0 先完成 api-surface 的贯通探针，随后再验记忆与人格行为，不能用“看到一个 section”“打印一次构造器”替代完整链路。

| 验收面 | 必须观察的结果 |
|---|---|
| 接收与归属 | 已接收且不回复的参与者消息仍在；源事件重放只记一次；自动注入不记成人物发言；身份更正不复制根事件；第三人被正确指称 |
| 请求作用域 | A/B会话交错组装，最终messages/system prompt与冻结快照匹配；先实测request/context字段，若只有元数据则改用请求准备入口或受控调试观察实际内容；旧版本不串入新请求 |
| 两种梳理 | sleep 与 on_write 都按同一高水位增量提交；切换后不重算已提交根事件 |
| 提交故障 | 每个文件写入和提交边界中断，恢复后无半次版本、无重复经历、未消费 H1 仍在 |
| 有限容量 | 实例总量与 bytes 有实测；原文自然淘汰后重要概括可用；源不可读缺口可见；不强迫睡觉 |
| 自主行为 | 记录人格决定与实际执行；没有暗藏固定等待、发送上限、印象门槛或承诺 SLA |
| 睡眠与重启 | 睡中无 assistant 输出；不同对象来信保留；醒来接收一次汇总；重启不永久静默或重复发送 |
| 主动交付 | idle/关闭会话/多通道目标、出队和实际输出贯通；急停取消未交付工作；未知交付不假报成功 |
| 撤销与重建 | 明确遗忘后相关概括不继续命中，回放旧宿主日志不会复活；自然淘汰不等同撤销 |
| 成本与效果 | 真实调用与 token 对账；离线比较仅锚与演化人格，保留人格变异，不以条目数量强制达标 |

早期P0需要逐项解决的宿主接入问题包括：请求内动态注入作用域、稳定源事件与流式最终事件映射、persona_decide 所需控制回路、reject 的真实消费语义、idle agent 启动/取消/交付确认、完整临时过程来源。这些问题的现行实测与未覆盖项见当前管理/渠道验收，不能用未经实测的“能力齐备”盖过去。研究支持设计探索，不能替代上述执行证据。

## 0.4.1 聊天渠道、外观与声音适配

DSH设置沿用宿主的颜色、字体和透明背景，使用可换行页签与设置分隔行，不另设主题选择器或品牌页眉；第七页“聊天渠道与语音”把已有兼容桥的参数折叠为高级配置，尚未实现扫码或接管桌面登录。该页适配用户已有QQ、微信软件的普通私聊/群聊。QQ适配OneBot11/NapCat，微信需要兼容OneBot12本地桥；微信官方接口当前不提供本方案所需普通群聊能力。默认没有listener，用户明确启用后仅在本机提供桥事件回调；个人网页和Telegram是预留接口，不挂载手机网页主入口。

平台、账号、房间、实际发言者、消息ID和平台发生时间作为真实环境事实保留；每发言者＋房间的原生通道仍共享同一个人格，外部ID和昵称不自动成为personId。接入范围是用户选择的连接边界，空范围未接入，显式*才开放相应全部对象/群；没有被@、主动次数、最短间隔或话题资格规则。原件经原生inbox持久，最终正文只有平台桥真实消息回执后才计实际说过，unknown不自动重放。

当前五工具追加persona_voice供人格按需查看真实音色目录和自主选择，用户指定模式优先。IM音频使用Windows System.Speech生成WAV，再取平台音频回执；rate近似SAPI音级、pitch:false，不克隆音色、不硬映射性格标签或强迫每轮选声。voice-only缺能力明确失败，both可保留真实文字交付并标语音不可用。技术字段和容量以persona-schema第14节为唯一权威；实际操作与验证见[聊天渠道接入](../../channel-integration.md)。
