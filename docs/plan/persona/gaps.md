当前实现（0.5.0）：产品名`dsh-Xiangxu-Persona`，包名`dsh-xiangxu-persona`，预设展示名“相续人格”；内部presetId `persona-memory`与数据契约`persona-memory/3`保留兼容。原生八页设置沿用DSH宿主样式，保留主动联系／现在叫醒的日常说明，新增官方QQBot／微信iLink扫码、实际能力许可、形象档案与可选图片／视频接口；高级OneBot保留。陪伴预设在普通DSH／IM／主动／唤醒中仅提供七个人格工具，不继承子agent派发；其它预设与内部原生接收通道不变。平台未实现的动态、通话或群能力不冒称可用，服务默认关闭、本人扫码和真实供应商输出仍需实际环境验证。当前入口与证据见[管理说明](../../management-ui.md)、[渠道接入](../../channel-integration.md)与[形象创作](../../media-and-identity.md)；研究和旧版本结果保留历史含义。

修订日期：2026-10-26。适用设计：`persona-memory/3`。本文件替代旧版按多租户隐私与人格硬闸门组织的缺口表；不把已撤回的建议继续写成待办。字段以 `persona-schema.md` 为准，流程以 `architecture.md` 为准。

## 1. 底层技术问题

| ID | 触发与后果 | 实施动作 | 验收与消费位置 |
|---|---|---|---|
| T01 源事件去重 | 回放、恢复或重试把一次经历记成多次 | 源会话/事件稳定键；关联摘要不造新经历 | 重放同事件，不新增源记录或机械增加支持；写入/梳理 |
| T02 归属准确 | A的话归B，群里说话者被抹掉，会话切换被当换人 | 环境线索供人格判断；内部人物关联与真实说话者分开，未知暂存可后关联 | 跨环境熟人、同名、误认纠正；环境/写入/检索 |
| T03 接收与回复解耦 | 决定等待、不回或睡着，已接收事件未进入后续材料 | 已接收范围内先记录，回复计划另存；不强制接收全部群聊闲谈 | 睡中/等待后可回顾已接收原话；接收/队列 |
| T04 请求共享变量 | 交错请求使用另一次动态提示 | 请求内固定环境/人物/版本/组装文本 | A、B交错时实际请求无误归属；注入 |
| T05 热区误删 | 整理只读部分，成功却清空所有；新消息丢失 | 固定输入截止，分页游标，只清已提交消费范围 | 整理中新输入下一批仍在；梳理/存储 |
| T06 半批提交 | 索引成功人格失败，重试形成不同半成品 | 批次journal、输入版本、结构校验、提交标记、幂等 | 在每个提交边界中断可恢复；所有派生消费者 |
| T07 自然遗忘误撤销 | 原文淘汰导致重要概括、印象和编码全失效 | 自然淘汰仅改变来源可用性；概括可留摘要 | 原文自然淘汰后仍能理解重要记忆；检索/人格 |
| T08 明确纠正复活 | 用户纠正或forget后，重建/回滚又带回已撤销内容 | 独立撤销记录先于重建生效；按实际语义处理关联概括 | 纠正/forget后重建不复活；记忆更新 |
| T09 临时上下文不完整 | 只有摘要却声称保留全部，无法解释来源缺失 | 原件缓存与trace引用分开；分页读取，缺源标明 | 取回可用原件，对失效引用如实降级；热区/梳理 |
| T10 容量失控 | 记忆、热区、诊断或备份无限增大 | 全实例字符目标+实际字节监测；有界引用、暂停冗余副本、回补游标 | 临界测试不无限增长、不强制睡，缺口可见；存储 |
| T11 睡眠恢复错乱 | 整理锁被当睡眠，重启后永久静默或乱发 | 业务睡眠决定、进程锁、调度任务分开恢复 | 睡中静默、醒来汇总、强退恢复；调度/输出 |
| T12 自选调度未执行 | 人格选一小时后再想，实际却固定十分钟或永不再想；选择倾听却被强加计时 | 持久时间及事件条件，到选定时间或事件才触发；调度器不裁定内容 | 定时计划不被无新消息跳过，事件型倾听不被强加检查；主动/睡眠 |
| T13 入队误报交付 | agent空闲/关闭或路由错误，消息未见却算已发 | 明确人物与目标通道；记录入队/启动/实际assistant事件 | 空闲、多会话、关闭恢复、重启不重复投递；发送 |
| T14 成本和上下文低估 | 把发送数当判断调用数、单段token当整请求 | 调用分类计数；统一tokenizer及实际路由/模型窗口 | 判断不发仍计费用，超窗有明确分配；LLM适配/组装 |
| T15 配置与Schema分裂 | 同字段枚举不同、未定义工具输出、边界软语义读成硬禁令 | 唯一Schema和版本；读写端共用同一契约 | 正反例能解析，旧版本显式迁移；所有模块 |

这里的“验收”检查程序是否忠实接收并执行人格决定。不会因人格误判人、选择不履约、暂时烦人而判程序故障。

## 3. 不再作为缺口追补的旧要求

- A的内容绝不进入B的任何上下文、跨对象只许管理员查看：没有用户授权这套多租户制度。保留T02/T04/T13，允许带真实主体的跨对象回忆。
- 只合并承诺/边界文件却继续全量扫描、强制履约或拦截输出：只改存储位置没有贯彻自主性，已退出当前设计。
- 三份独立证据、固定支持度/置信度、二十轮冷启动禁令：不是人格形成资格，不能以统一Schema再加回来。机械去重仍按T01执行。
- 固定人类作息、三天自动强制睡、固定三秒/十分钟行为节拍、未回就退避：当前以人格决定为准。物理容量边界按T10处理。
- 原始流永久不删、源原文淘汰即撤销全部概括：与有限记忆和自然遗忘冲突，已改成T07/T08的两种语义。
- 三天长满十二至十八条签名、主动接受率必须达到某百分比、承诺必准时：不作为人格效果验收；条目上限和token预算只服务资源控制。

## 5. 0.5.0新增接口仍须实测的边界

本人官方扫码及平台账号资质、真实私群收件／媒体发送、真实供应商输出质量、长期形象一致性需要用户自己的环境；模拟平台／provider和原生SDK不替代这些结果。微信官方群聊、动态与RTC未实现，不通过开放权限开关假装完成；官方本机WAV发送缺编码链。外部作品字节需另备份，元数据清单不等于文件备份。以上是接入与保真问题，不新增人格判断门槛。
