# QQ等待登录与0.13.4恢复补修

本文保留0.13.4当时的故障、验证与加载记录。后续0.13.5的[技术补修](0.13.5-technical-safety-fixes.md)不新增生产登录／QQ实测，也不把记忆碰撞、旧发送和关闭顺序问题认定为此前DSH Host启动超时的根因。

适用于dsh-Xiangxu-Persona 0.13.4，核对日期2026-10-29。本页把技术登录状态、人格状态和真实聊天送达分开报告；不规定人格必须回复，也不把技术故障解释成人格自主沉默。

## 这次为什么没有回复

本次定位时DSH宿主正常，受管QQ仍在等待登录，来信没有进入模型。人格处于“清醒”只说明人格运行状态，不能证明QQ账号已在线或事件通路已接通。

历史账号快登列表包含正式账号，但一次官方`SetQuickLogin`调用返回HTTP200、业务`code:-1`，QQ明确提示“你的用户身份已失效，为保证账号安全，请你重新登录。”HTTP请求成功不等于QQ登录成功。本次没有取得快登成功、模型处理这批来信或平台送达回复的证据，仍需本人扫码；不能把没有进入模型的消息解释为人格选择不回应。

先前Chrome图形进程的大额内存占用与Host分配失败是上一次环境故障，释放内存并重启成功不证明后续QQ始终在线。本页不把本次等待登录笼统归因为长时间未关机。

## 本补丁改变什么

受管QQ真正新启动时，程序只在以下事实同时成立时，向官方NapCat传递单一`NAPCAT_QUICK_ACCOUNT`：已保存恢复意愿、当前流程仍持有相同恢复意愿、当前人格及记忆库归属一致，且已启用的QQ兼容桥所保存账号与API端口匹配。该值取已保存账号，不接受猜测账号或额外账号列表；继承环境里的其它快登账号／密码不会被沿用。

首次接入继续由本人选账号扫码。普通UI状态读取和poll不调用QuickLogin、不反复换码；新启动的快登若被QQ拒绝，仍按平台返回说明重新登录。该参数只允许官方组件尝试恢复已有登录，不保证旧身份有效，不绕过手机确认，也不修改人格、原账号范围、能力许可或记忆。

“相处”页新增QQ连接提示，与人格“清醒／休息”分开。已保存配置但仍等待登录、当前人格尚未核实、管理状态未确认、准备失败和上次确认连接分别显示；提供“检查QQ连接”的直接入口。提示只读取现有快照，不在相处页新增后台轮询、主动探测、重启或模型调用。旧快照注明上次核查，不能冒充当前实时在线。

## 用户怎样处理

1. 在相处页看到“QQ连接：等待登录”时，点“检查QQ连接”，进入 **连接 → QQ**。
2. 当前页面出现真实二维码后，用对应QQ账号的手机扫码并确认。二维码过期时按页面提供的“重新生成二维码”取得新码；没有当前二维码就先查看实际错误，不重复扫码旧截图。
3. 等待账号在线与接入核验。手机确认、QQ在线、已接入人格和实际发回消息是不同阶段，以页面和实际回执为准。
4. 若仍无回复，依次检查来信是否接收、模型是否启动、人格是否形成发送决定、平台是否确认送达。状态未知时不反复发送同一内容，也不通过清空人格修复连接。

完整首次准备、停止与恢复边界见[个人QQ接入说明](qq-one-click-setup.md)。账号资料、空间和未接线能力见[实际能力表](account-capabilities.md)。资料内容、换头像／昵称的时机、社交对象、记忆和回应仍由人格自主判断。
