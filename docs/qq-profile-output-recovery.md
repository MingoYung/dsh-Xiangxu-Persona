# QQ资料与文字输出修复（0.13.3）

0.13.3修复两个底层技术问题：正常上下文中的来源数量超过内部自我档案旧上限，导致资料写入失败；桌面专用的卡片格式被原样发送到QQ等文字聊天渠道。人格仍自行决定是否修改资料、改成什么、什么时候改，以及记住什么。

本轮仅登记代码改动和隔离验证。真实桌面尚未加载／重启本补丁，本轮新增真实模型与QQ资料修改尚未验收；QQ资料修改按用户安排自行测试，其他社交媒体继续显示未测试。0.13.2的登录恢复、私聊与群聊历史结果见[上一补丁说明](qq-reply-recovery.md)，不能作为本补丁已生效的证明。

## 自我档案来源容量

自我档案来源按真实来源身份去重后，计数上限从16个sourceRefs／32个sourceRecordIds对齐到8192／16384，与现有过程依赖扫描边界一致。不同来源不会因为内容相似而被合并；当前描述、真实来源和有限历史不为了凑容量被静默裁剪。

原有内容容量继续成立：initial/current各合计2400个Unicode字符、整个档案65536字节（64KiB）、历史最多8版，写入继续核对expectedVersion、单写者、事务和实例容量。来源计数上限与64KiB是同时生效的独立边界，不保证任意8192条来源都可写入；真正超出容量仍明确失败，原资料保留。字段权威见[方案第20节](plan/persona/persona-schema.md#20-自我档案初始化与交流定位090)。

## 外部文字渠道的显示与保存

QQ等文字渠道不提供DSH桌面卡片控件。对当前外部文字会话过滤已知宿主genui:fence提示，避免继续推荐无法使用的桌面展示格式；普通DSH会话保持原有宿主展示能力。

外部通道的显示能力另以简短的persona-memory:channel-output技术事实节提供，避免它只放在可裁剪的环境片段中而被默认上下文预算省略。该事实只说明普通文字可显示、桌面卡片不可渲染，不决定人格的表达内容或态度。

如果原生回复仍包含dsh-ui卡片，适配层以版本化dsh-plain/1投影转换为可阅读文字：保留标题、说明和可读项目；不能转换的图形、控件、未知或损坏组件给出明确显示提示，不把按钮说成已经执行。普通文字、一般Markdown和代码示例保持原意，转换不执行卡片代码、不访问链接，也不另发模型请求。

发送内容、已送达后进入交流记忆的内容、回执校验和重载恢复使用同一投影，分别记录原生正文与实际送达文字的摘要。DSH原生消息保留原件；旧回执仍按其当时实际发送的原文核对，不把历史卡片源码事后冒充已发送的纯文字。超出转换技术容量明确报告，不能把不完整输出标成完整转换。

宿主原始输出保留为过程资料时，单条或累计临时缓存满后仍可转为host_trace并回查；定位使用转换前的真实hostKind，外发投影造成的过程分类变化不改写原生事件类型。这样可回查宿主原件，并避免已送达／未确认输出改分类后失去原件定位；交流记录仍按实际送达内容及回执确定。

## 内部资料与平台账号操作

persona_introspect/action:update_self修改的是人格内部self/profile.json，不会替人格修改QQ昵称、头像或资料卡。已授权平台账号自己的资料使用persona_platform的账号能力分支，QQ对应profile.update；实际支持、授权、在线状态与最终结果按真实工具回执报告，见[账号能力](account-capabilities.md)与[QQ账号操作](qq-account-operations.md)。

这一区分只澄清工具用途与执行结果。人格仍自主选择内容和时机，不指定昵称、头像或背景，不增加更新频率、逐次批准、人格进化门槛，也不强迫它修改资料。
