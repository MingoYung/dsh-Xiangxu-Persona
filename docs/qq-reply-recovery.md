# QQ 无回复与记忆缺口提示修复

本页记录 0.13.2 修复的范围和验证状态。数据契约继续为 `persona-memory/3`，统一时间线仍沿用 0.13.0 的契约。人格仍自主决定是否回复、记什么及如何理解经历；技术故障与人格选择分别显示。

## 这次无回复发生在哪里

本次故障诊断时确认 QQ 兼容桥在线，来信后的原生模型请求在必要人格上下文校验处失败。对外错误为 `PERSONA_CONTEXT_UNAVAILABLE`，直接原因是 `PERSONA_CONTEXT_PROJECTION_MISSING`；隔离的真实 DSH 宿主复现进一步定位到 `live_missing`。这些失败发生在模型调用之前，不能解释为人格自主选择不回复。第一阶段修复加载并重启后已由用户完成手机登录，正式 QQ 私聊与群聊各一条真实往返已验证。后续辅助压缩请求补修已完成隔离验证，并按用户选择经正常重启加载；这次重启后的完整登录二维码已在本机显示，等待用户再次手机扫码确认，当前连接尚未恢复。两阶段的证据范围另见下表。

同一个请求先在 Agent 范围组装一次人格资料，再由陪伴工具范围组装一次。第二次调用没有继续传递原请求上下文，导致校验仍持有第一次的快照，而最终请求使用了第二次的快照。校验因此拒绝了这次请求。

修复让第二次组装继续传递原请求上下文，使登记的快照与实际发出的请求一致。必要人格上下文的最终校验继续保留；没有通过删除校验、使用任意旧快照或缺少人格资料仍调用模型来恢复回复。技术诊断仅提供固定原因枚举，不记录人格正文或访问凭据。

## “44 处记忆缺口”代表什么

这次实际检查到的 44 项未解决记录全部属于 `hot_dependency_scan_incomplete`，即临时过程资料的来源依赖尚未完整核清。按来源事件去重后为 29 个事件：16 个工具结果事件和 13 个助手消息事件，没有以 `user/message` 为来源的记录。相关原始宿主事件仍可读取。本次数字来自特定故障现场，不代表其他用户的实例状态。

工具分页结果可能只包含一段 JSON 文本，后续同一轮过程资料也可能依赖这些片段。系统不能据此假定所有来源都已找全，否则明确遗忘或撤销来源时可能遗漏关联资料。因此此类过程资料会保留待核查状态，不能把数量直接解释为丢失了同样数量的真人消息，也不能把原件仍保留解释为所有依赖均已完成回补。

新版管理界面分别统计过程资料依赖问题、交流原文保存问题及其他问题，并区分记录数与来源去重数。未知原因采用保守说明；不清空历史问题记录，也不放宽分页片段的依赖与撤销保护。

## 遇到类似情况时

先查看相续人格的运行状态及 QQ 连接状态。桥在线只说明连接端仍在运行；人格资料加载失败、模型服务失败和发送失败需要分别检查。设置页无法正常读取时，可使用[报告问题](support.md)生成最小诊断摘要，并附上操作步骤、预期结果与实际现象。

不要为了排查而清除或重建正式人格，也不要把完整记忆库、私聊、账号配置、令牌、Cookie 或登录二维码放入公开 Issue。正常重载后仍需以当前状态和真实收发结果确认恢复；如需重新扫码，连接页会说明原因，不把反复扫码作为一般排查步骤。
