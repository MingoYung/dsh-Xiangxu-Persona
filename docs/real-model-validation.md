本轮确实修正了以下执行问题：

- 原生工具的可选 JS 字段含 `undefined`，DSH 在 render 之前要求 lossless JSON，导致实际效果已落却返回错误。现在在真实 raw tool 边界归一 JSON，并补完整嵌套参数 schema。
- `sourceRefs` 原先说明不足，模型猜来源键、混用 channelId/sessionId。现在说明真实键的形状、当前来源默认范围，并在执行前验证键存在；拒绝不存在的键，不替模型猜。旧不可执行 effect 明确失败，I/O 错误仍可恢复。
- 注意范围只阻止记忆写入，曾未过滤原生输入；补齐后又在真实测试中发现误阻本轮已接收的回复。最终实现区分新输入准入与已明确选择的本轮回复，睡眠、等待和跨目标决定继续按计划执行。
- 跨目标原生决定曾缺执行桥。现在同目标复用原生生成，其他合法目标经真实核心回复、outbox 和实际交付确认；源通道不多发一遍。
- 环境事件原先缺 DSH 生产者。现在消费实际可见的通道/环境变化和配置更新，不添固定周期心跳。
- 多组认人的来源范围曾可能串到当前窗口。现在历史原话、路由和当前上下文使用同一明确范围；显式只选 B 不改 A，A+B 可由模型认成同一人，空来源仍可凭环境认人。
- 已撤销原话/索引曾在工具结果临时副本中继续存在。现在按结构化来源、记录 ID 和实际上下文组清理过程副本，并在 capture、prepare、open、恢复和 trace 溢出边界检查。旧无依赖副本保守清理并记诊断；没有扩大成其他真实根撤销。
- 工具结果现在报告真实的 `identityAssociation`，区分所认人物、所选来源会话和实际当前路由。它不因为当前路由不同就自动强绑或收费重试。

遗忘净化的原库预检没有发模型请求：清除了 51 份旧 B 临时过程副本，指定旧检索缓存不再可供下一次整理。17 份业务文件 SHA 保持相同，`revokedSources` 仍只有原来选定的用户根和助手根。合法的撤销指令及事后说明保留其否定语义。新根可以再次表达完全相同词句并正常保存，这一点有隔离回归，证明没有做词句禁令。

工具游标发生过模型抄错一字符和旧游标误用。服务明确拒绝后，模型以 fresh query 自行恢复，最终遗忘和补关联均实际完成。这些错误及其用量保留为 `completed_with_protocol_recovery`，没有被改写成全程无错，也没有自动替模型修游标或绕过参数校验。

B2 的补关联只针对模型实际选择的新来信。A2 的路由条目与此前深相等，B2 关联到原周闻，原记录 ID、正文、来源时间保持不变且仍只有一份。两条识别前的 B2 助手记录仍在 unknown 暂存：阶段 06 的回忆答复、阶段 07 的投递消息。它们已保存、未丢失；模型没有选择这些根，因此程序没有用 `sessionId=身份` 的假定将整段历史强行重归。不能声称“所有历史都已自动认完”。

独立审查未发现固定每日次数、最短交流间隔、沉默处罚、强制睡眠、主观印象成立门槛、边界话题硬拦截、承诺履约器、按主动来源降低检索权重或跨人物绝对 ACL。结构校验、来源定位、可达目标、分页、资源上限、去重和用户急停仍在。实际发现过的自主决定执行干扰已经修正，并保留在上面的失败记录中。
