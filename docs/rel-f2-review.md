## 重启后的 QQ 签名检查补修

正式加载后发现 `NAPCAT_QQ_SIGNATURE`。只读对照确认 QQ 的腾讯签名有效，失败来自 Windows PowerShell 5.1 继承 PowerShell 7 的模块路径；尚未走到账号登录阶段。适配器只清理 Windows PowerShell 子进程环境中的 `PSModulePath`，保持原验签、进程归属和权限条件，不改父环境或人格决定。受影响测试162/162通过，原生 Node 与 DSH Electron Node 验签对照通过，详见[Windows 兼容说明](windows-powershell-compat.md)。补修后的实际 QQ 登录与收发分别验收，不从设置已保存推断在线。

后续发现 NapCat 登录管理接口与 OneBot 动作接口状态不一致：前者报告重连，后者在线；唯一维护通知获发送回执且用户手机确认收讫。它证明这一条出站，不代替人格模型、入站、群聊或原生资料能力验收。UI现在将单侧管理结果表述为“登录管理状态待核对/登录管理接口正在重连”，不据此断言消息必定不可用，无当前有效二维码时不直接要求扫码。保留原始状态、权限、扫码和轮询条件，不强行把管理接口改为在线。两套前端fixture64/64通过，含状态冲突及有效二维码边界。
