# 0.10.1 界面、检索与上下文验收

本轮修复可选功能的操作可见性、记忆翻页、B站连接说明与同源旧人格系统快照重复投影，继续使用同一个人格、persona-memory/3和既有八工具。没有修改人格控制指引CONTROL_GUIDANCE，也没有加入强制回忆、主人权重、情绪阈值、整理频率或固定遗忘规则。0.10.0的功能说明与当时验收保留在[接入与检索说明](integrations-and-retrieval.md)；旧875项或SDK40项不能直接当作本轮已重跑。

## 界面从用户能看见和读懂的地方修起

原生下拉选项使用系统Canvas／CanvasText与选中、禁用色，避免透明主题中弹出菜单背景与白字混在一起；页面仍沿用DSH主题，没有增加一套独立主题。此修复不等于已经证明所有系统、主题和缩放比例都无问题。

记忆、已知人物和关联候选页在列表上、下都有首页／上一页／下一页控件，按本页实际范围显示页码，成功后才更新翻页位置。每页12条；关联搜索仍最多给出本次前100个候选，这不是全库条目总数，也不限制人格可以继续换线索搜索。旧游标失效时显示原因并让用户回到第一页读取最新结果，不能用旧结果冒充新库。切换实例、页面或查询后，迟到的响应不能写入当前实例的页面或人物缓存。

B站授权中刷新页面后，可明确点击恢复本轮二维码；有效时复用同flow，已过期才取得新任务。只读打开页面不自动创建新登录任务。四项能力用B站语境中的中文名称，新增授权确认框与实际选项使用同一个标签，避免把评论、回复或私信误读成其它平台的泛化动态能力。标签修正不增加任何许可。

## B站恢复连接与真实账号边界

仅当已启用且本机有凭据时，服务启动做一次普通GET /nav账号核实。未启用／未配置保持离线；核实失败记录实际状态，不循环重试，也不阻断独立人格核心。持有Cookie不等于账号仍有效，后续可在面板明确核实；该启动检查不会发表评论、私信、分享或自动浏览视频。

用户在本轮已经完成本人B站扫码，并仅授予feed.read读取能力。真实Flash读取的实际结果与调用数量在末尾验收节汇总，不能据登录成功推定全部读取成功。评论／回复／私信／分享均未因这次读取许可而开放，不把只读验收说成平台外发验收。QQ尚无NapCat等兼容桥，不能声称个人QQ或群聊已完成真人往返；未配置状态须如实说明。

## 字幕轨来源：身份回显还不够

真实读取中发现，旧的未签名/x/player/v2即使回显相同aid／bvid／cid三元组，也可能返回不属于所选视频的字幕轨；仅核对这三个返回字段不足以建立轨来源对应。现改为签名/x/player/wbi/v2，请求绑定已核对的视频aid／bvid与所选cid，返回三元组不匹配时拒绝取字幕，不回退旧未签名接口。

对可辨识的AI字幕资产命名，另外检查其中编码的aid／cid前缀；明确属于其它媒体时返回来源不匹配，不把那份文字贴到当前视频。未编码这些ID的轨仍标assetBinding:not_encoded，不冒充已完成该项绑定。工具保留sourceBinding、subtitleTrack的轨ID／源host／URL哈希、内容contentHash和实际段时序／分P／续读位置；不公开原始签名URL。续读可带已返回的contentHash，来源字节变化时拒绝把两版拼接成一份。

这些检查只核平台声明与可验证的技术来源。coverage.contentCorrespondenceAssessed保持false；字幕内容是否确实对应视频、怎样理解它，仍由人格结合实际材料判断。没有按标题关键词删词、替换字幕、语义纠正或强迫接受该轨。修复后的第三轮真实Flash样本记录为observed，具体请求计量与结果限制保留给末尾最终验收，不把一个样本推广为所有视频永远对应正确。

## 本轮处理哪种上下文重复

DSH保留会话事件与向模型投影消息是不同层。适配器只在能够识别当前会话、受信宿主system-prompt来源、完整协议指纹和相续环境目标的同源旧系统快照时，使用宿主原生startsRequestSeries重新开始系统投影；不直接删改Session、持久事件或用户／助手／工具消息。遇到foreign／无法识别／投影不一致的系统节点时保守保留原历史，不能为了减量清掉别的系统指令。

当前协议与普通交流指引和最新动态参考仍正常提供。CONTROL_GUIDANCE内容未改，去重不会替人格决定关注什么、记什么或如何回应；近期对话不因这轮修复被粗暴截掉。原生重新开始请求序列可能降低模型服务的热缓存命中，不能承诺每次都更快或更便宜。真实请求中有效系统快照数量按验收样本统计，不能由代码分支推断所有未来请求永远只有一份。

## 2970、短期过程与会话压缩分别是什么

| 项目 | 实际含义与限制 |
| --- | --- |
| 动态参考2970 | 人格、关系、检索、深刻参考、自我资料等动态snapshot的总预算；缺少真实tokenizer时默认按UTF8字节估计并标注utf8_bytes_estimate。不是整个DSH请求的精确token总上限 |
| 当前会话消息 | 用户／助手／工具历史、系统指引、工具定义与宿主封装另占输入；不能从动态预算倒推出最终实际请求大小 |
| 预设的宿主compaction | 仓库cordis.patch.yml中persona-history-basic的maxTokens4096是摘要输出预算，headroomTokens8192是预留余量；默认thresholdRatio0.8／retainRatio0.16，deepseek-official／deepseek-flash模型策略改用thresholdRatio0.049152与retainTokens8192近期尾部。它们不是整包输入硬帽，也不表示每次用满；实际触发与计量仍取宿主实现和实际模型规格 |
| H1短期过程 | 默认20万字符的过程存储目标，供必要的整理、来源追踪或回查，不是把整个热区每轮发送给模型 |
| C1／H1整理重叠 | 原始对话与过程材料在现有整理供料中可能重叠，本轮没有重写该机制，也没有借去重静默丢失原件 |

压缩配置的直接出处是[仓库预设](../cordis.patch.yml)，不是仅来自某台电脑的用户设置；本轮没有修改这份配置。默认计数回退见[createTokenCounter](../core/prompts.js)。

本轮取得的模型元信息为DeepSeek-V4.1-Flash：contextWindow为1,000,000，defaultMaxTokens为256,000，systemPromptUpdate为in-history。这些是模型元信息，不等于这次请求实际使用量；验收runner初始化明确指定maxTokens4096作为本次生成输出额度，也不能把它与压缩摘要输出4096混为同一请求或整包输入帽。最终实际请求／用量按下方验收记录。

本轮先处理可确认的同源旧系统投影重复；没有把必要对话删到某个臆测token值，没有用固定重要度决定保留谁，也没有用上下文紧张强制人格整理或睡眠。容量、原件保留与调用输入继续分别核对。实际用量只能按服务回执报告，不能以字符帽、摘要预算或缓存命中估算费用保证。
